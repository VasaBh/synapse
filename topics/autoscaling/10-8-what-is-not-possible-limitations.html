8. What is NOT Possible — Limitations

LimitationDetailsWorkaround
VPA cannot resize pods in-placeKubernetes in-place resize is alpha and unsupported in OpenShift. VPA must evict and recreate pods.Use VPA "Initial" mode to avoid restarts. Accept brief disruptions with Auto mode.
HPA cannot scale to zeroHPA minimum is 1 replica. It will never remove the last pod.Use KEDA (minReplicaCount: 0) or Knative (minScale: 0) for scale-to-zero.
HPA cannot use custom metrics nativelyHPA only supports CPU/memory from the metrics server. Custom metrics need an adapter.Use KEDA which acts as a metrics adapter and feeds external metrics to HPA.
Cluster Autoscaler requires Machine APIOnly works on IPI (AWS, Azure, GCP, vSphere). Not on bare metal UPI.On UPI bare metal, manually add/remove nodes. Or use assisted installer with MAPI.
VPA + HPA on same metric conflictsBoth try to control the same resource causing oscillation.Use VPA for right-sizing + KEDA for custom-metric horizontal scaling.
No native HTTP-based autoscalingOpenShift has no built-in way to scale on request rate without instrumentation.Instrument app (Prometheus), use Knative, or use Istio/Envoy metrics with KEDA.
Scale-to-zero has cold-start latencyFirst request after idle must wait for pod startup (container pull, app init).Set minScale: 1 for latency-sensitive APIs. Use readiness probes. Pre-warm with KEDA cron trigger.
