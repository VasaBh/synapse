4. How to Use External Load Balancers WITH OpenShift

The integration pattern places the external load balancer as the entry point, forwarding traffic to OpenShift nodes:

CLIENT REQUEST
|
v
+---------------------------+
|   External Load Balancer   |
|   (F5 / HAProxy / NLB)     |
+---------------------------+
/          |          \
v           v           v
+-----------+ +-----------+ +-----------+
| Worker    | | Worker    | | Worker    |
| Node 1    | | Node 2    | | Node 3    |
| [Router]  | | [Router]  | | [Router]  |
+-----------+ +-----------+ +-----------+
|             |             |
v             v             v
+-----------+ +-----------+ +-----------+
| Service   | | Service   | | Service   |
|  -> Pods  | |  -> Pods  | |  -> Pods  |
+-----------+ +-----------+ +-----------+

4.1 Health Check Configuration

The external load balancer must health-check OpenShift endpoints to know which nodes are healthy:

  • API health check: GET /readyz on port 6443 (HTTPS). Must detect API server down within 30 seconds.
  • Router/Ingress health check: GET /healthz/ready on port 1936 (HAProxy stats port). Detects unhealthy router pods.

4.2 TLS Termination Strategies

There are three approaches to handling TLS when an external LB sits in front of OpenShift:

StrategyHow It WorksPros / Cons
SSL PassthroughExternal LB forwards encrypted traffic directly to OpenShift Router. No TLS termination on the LB.Pro: Simple setup, end-to-end encryption. Con: LB cannot inspect HTTP content, no L7 routing on LB.
SSL TerminationExternal LB terminates TLS, forwards plain HTTP to OpenShift Router. Certs managed on the LB.Pro: LB can inspect/modify HTTP. Con: Traffic is unencrypted between LB and Router (unless on trusted network).
SSL Re-encryptionExternal LB terminates TLS, then re-encrypts with a new TLS connection to OpenShift Router.Pro: Full encryption throughout. LB can still inspect traffic. Con: Double TLS overhead, more cert management.

4.3 Example: HAProxy External LB for OpenShift

# /etc/haproxy/haproxy.cfg
defaults
mode tcp
timeout connect 30s
timeout client 1m
timeout server 1m
# --- OpenShift API (port 6443) ---
frontend ocp-api
bind *:6443
default_backend api-servers
backend api-servers
option httpchk GET /readyz HTTP/1.0
option log-health-checks
balance roundrobin
server master-0 192.168.1.10:6443 check check-ssl inter 1s fall 2 rise 3 verify none
server master-1 192.168.1.11:6443 check check-ssl inter 1s fall 2 rise 3 verify none
server master-2 192.168.1.12:6443 check check-ssl inter 1s fall 2 rise 3 verify none
# --- Application Ingress (port 443) ---
frontend ocp-https
bind *:443
default_backend ingress-routers
backend ingress-routers
option httpchk GET /healthz/ready HTTP/1.0
balance roundrobin
server worker-0 192.168.1.20:443 check check-ssl port 1936 inter 1s fall 2 rise 3 verify none
server worker-1 192.168.1.21:443 check check-ssl port 1936 inter 1s fall 2 rise 3 verify none
server worker-2 192.168.1.22:443 check check-ssl port 1936 inter 1s fall 2 rise 3 verify none
