8. Decision Guide — Which Approach to Use?

RequirementRecommended ApproachComplexity
Basic internal service distributionKubernetes Service (ClusterIP) - already built-inLow - zero config needed
External access to HTTP servicesOpenShift Route (oc expose)Low - single YAML
Simple A/B testing or Blue/GreenOpenShift Route with weighted backendsLow - CLI commands
Canary with header-based routingService Mesh (Istio VirtualService)Medium - requires mesh install
Automated progressive deliveryArgo Rollouts + Service Mesh or RoutesMedium - GitOps tooling
External non-HTTP services (DB, MQ)MetalLB (on-prem) or cloud LoadBalancerMedium - network config
HA cluster entry pointExternal LB (F5/HAProxy) or cloud NLBMedium - infra setup
Cross-site failover (Prod to COB)GSLB (F5 GTM / Route 53 / Azure TM)High - DNS + health checks
Active-Active multi-siteGSLB + bidirectional data replicationHigh - complex data sync
