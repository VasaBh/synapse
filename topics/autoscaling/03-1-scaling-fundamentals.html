1. Scaling Fundamentals

Scaling is the process of adjusting compute resources to match application demand. In a containerised platform like OpenShift, scaling operates at multiple layers — from individual pod resources to the number of pod replicas to the number of cluster nodes.

1.1 Horizontal vs Vertical Scaling

AspectHorizontal ScalingVertical Scaling
What changesNumber of pod instances (replicas). Adding/removing copies of the application.CPU and memory allocated to existing pods. Making each instance bigger/smaller.
DirectionScale Out (add replicas) / Scale In (remove replicas).Scale Up (add resources) / Scale Down (reduce resources).
Best forStateless applications, web APIs, microservices. Traffic-driven workloads.Stateful apps, databases, single-threaded workloads, right-sizing resource requests.
DisruptionNone — new pods are added alongside existing ones.Pod must be restarted with new resource values (VPA evicts the pod).
OpenShift toolHPA, KEDA, Knative, manual oc scale.VPA Operator.

1.2 Node-Level Scaling

Beyond pods, OpenShift can also scale the cluster infrastructure itself by adding or removing worker nodes. This is infrastructure-level horizontal scaling managed by the Cluster Autoscaler and Machine Autoscaler, which interact with the cloud provider or virtualisation platform to provision new VMs when pod demand exceeds current cluster capacity.

COMPLETE AUTOSCALING LAYERS IN OPENSHIFT
Layer 1: Pod Replicas (Horizontal)             Layer 2: Pod Resources (Vertical)
+----------------------------------+           +----------------------------------+
|  HPA / KEDA / Knative            |           |  VPA Operator                    |
|                                  |           |                                  |
|  Scales: number of pod replicas   |           |  Scales: CPU & memory per pod    |
|  Trigger: CPU, memory, custom     |           |  Trigger: historical usage data  |
|           metrics, concurrency    |           |  Action: evicts + recreates pods  |
+----------------------------------+           +----------------------------------+
Layer 3: Cluster Nodes (Infrastructure)
+--------------------------------------------------------------+
|  Cluster Autoscaler + Machine Autoscaler                      |
|                                                              |
|  Scales: number of worker nodes (VMs)                        |
|  Trigger: pods in Pending state (no schedulable node)         |
|  Action: adds/removes Machines from MachineSets              |
+--------------------------------------------------------------+
