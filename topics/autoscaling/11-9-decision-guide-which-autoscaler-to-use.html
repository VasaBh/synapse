9. Decision Guide — Which Autoscaler to Use?

AUTOSCALER DECISION TREE
What do you want to scale ON?
|
+--> CPU / Memory only?
|       |
|       +--> Need scale-to-zero? --YES--> KEDA (CPU trigger)
|       |
|       +--> No scale-to-zero? ---------> HPA (built-in)
|
+--> HTTP traffic / requests per second?
|       |
|       +--> Can modify app code? --YES--> FastAPI Prometheus + KEDA
|       |
|       +--> Cannot modify code?
|               |
|               +--> Service Mesh? --YES--> KEDA + istio_requests_total
|               |
|               +--> No Mesh? -----------> Knative Serverless
|                                     or   HPA on CPU (indirect)
|
+--> Queue depth (Kafka, RabbitMQ)?
|       |
|       +--> KEDA with Kafka/RabbitMQ trigger
|
+--> Concurrent connections / WebSockets?
|       |
|       +--> Knative (concurrency-based)
|       or   KEDA + custom Prometheus gauge
|
+--> Right-size pod resources?
|
+--> VPA Operator (Off mode first, then Auto)
ALSO need cluster to grow/shrink nodes?
+--> Cluster Autoscaler + Machine Autoscaler (IPI only)
