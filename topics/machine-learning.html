Section 01

ML Landscape & Taxonomy

Machine Learning is the practice of building systems that learn patterns from data rather than executing hand-written rules. It is the foundation of all modern AI — from classical tabular models to the Transformer architectures that power LLMs.

MACHINE LEARNING ┌──────────────────┬──────────────────────┐ Supervised Unsupervised Reinforcement │ │ │ ┌──────┴──────┐ ┌───────┴──────┐ ┌───────┴──────┐ Regression Classification Clustering Dim. Reduction Policy │ │ │ │ Learning Linear Logistic K-Means PCA PPO Ridge/Lasso Random Forest DBSCAN t-SNE/UMAP DQN XGBoost XGBoost Gaussian Mix. Autoencoders RLHF

Learning Paradigm Comparison

ParadigmInputGoalExamples
SupervisedLabelled (X, y) pairsLearn mapping X → ySpam detection, house price prediction, image classification
UnsupervisedUnlabelled X onlyDiscover hidden structureCustomer segmentation, anomaly detection, topic modelling
Semi-supervisedSmall labelled + large unlabelledLeverage unlabelled dataDocument classification with few labels
Self-supervisedData itself creates labelsLearn representationsGPT pre-training (next token), BERT (masked token)
ReinforcementEnvironment + reward signalMaximise cumulative rewardGame playing, robot control, RLHF for LLMs

The ML Workflow

Raw Data │ ├─► EDA (Exploratory Data Analysis) │ └─ distributions, correlations, missing values, outliers │ ├─► Feature Engineering │ └─ encode, scale, create, select features │ ├─► Train / Validation / Test Split │ └─ 70/15/15 or 80/10/10 (never touch test until final eval) │ ├─► Model Selection + Hyperparameter Tuning │ └─ cross-validation, grid/random/Bayesian search │ ├─► Final Evaluation on Test Set │ └─► Deployment + Monitoring
Data quality over algorithm choice A simple linear model on clean, well-engineered features usually outperforms a complex model on raw data. In practice, 80% of ML project time goes to data preparation — and that investment pays off far more than model architecture choices.
Section 02

Linear & Logistic Regression

Linear and logistic regression are the workhorses of interpretable ML. They are fast, require little data, and produce human-readable coefficients. Understanding them deeply — including their loss functions and regularisation — is essential for all ML engineers.

Linear Regression

Model: ŷ = w₀ + w₁x₁ + w₂x₂ + ... + wₙxₙ Loss: MSE = (1/N) Σ(yᵢ - ŷᵢ)² Optimise: Gradient descent → wⱼ := wⱼ - α · ∂MSE/∂wⱼ Normal equation → w = (XᵀX)⁻¹ Xᵀy (exact, but O(n³))
VariantRegularisationPenaltyEffectWhen to Use
OLS (Ordinary Least Squares)None—No constraint on weightsFew features, low multicollinearity
Ridge (L2)L2λ Σwⱼ²Shrinks all weights toward 0Many correlated features
Lasso (L1)L1λ Σ|wⱼ|Drives some weights to exactly 0 (feature selection)Many irrelevant features
ElasticNetL1 + L2λ₁|w| + λ₂w²Combines both effectsMany features, some correlated

Logistic Regression

import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.model_selection import cross_val_score

# Pipeline: scale → regularised logistic regression
pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("clf",    LogisticRegression(C=1.0, penalty="l2", max_iter=1000)),
])

pipeline.fit(X_train, y_train)

# Coefficients → interpretability
coef = pipeline.named_steps["clf"].coef_[0]
feature_importance = dict(zip(feature_names, np.abs(coef)))
top_features = sorted(feature_importance.items(), key=lambda x: -x[1])[:5]

# Cross-validated AUC
cv_auc = cross_val_score(pipeline, X, y, cv=5, scoring="roc_auc")
print(f"CV AUC: {cv_auc.mean():.3f} ± {cv_auc.std():.3f}")
Logistic regression is a probability model, not just a classifier The output sigmoid(wᵀx) is a calibrated probability. Use predict_proba rather than predict when you need confidence scores for ranking, thresholding, or downstream decisions.
Section 03

Decision Trees & Ensemble Methods

Decision trees partition feature space into axis-aligned regions. Alone they overfit; combined into ensembles (bagging → Random Forest, boosting → XGBoost/LightGBM) they become the most powerful algorithms for tabular data.

Decision Tree split: ┌─────────────────────────────────────┐ │ age < 35? │ │ YES ──► income < 50K? │ │ YES → class: 0 │ │ NO → class: 1 │ │ NO ──► employed? │ │ YES → class: 1 │ │ NO → class: 0 │ └─────────────────────────────────────┘ Split criterion: Gini impurity or Information Gain (entropy)

Ensemble Strategy Comparison

MethodBuilds TreesCombines ViaReducesAlgorithm
BaggingParallel (independent)Average / voteVarianceRandom Forest
BoostingSequential (correct errors)Weighted sumBias + VarianceXGBoost, LightGBM, CatBoost
StackingParallel (diverse models)Meta-learnerBothsklearn StackingClassifier

XGBoost — Production-Grade Boosting

from sklearn.model_selection import RandomizedSearchCV

Random Forest

Best default for tabular data. Low hyperparameter sensitivity. Out-of-bag error estimation. n_estimators=100, max_features="sqrt".

XGBoost

Top Kaggle performer. Column/row subsampling, regularisation, GPU support. Use early_stopping_rounds always.

LightGBM

10–100x faster than XGBoost on large datasets. Leaf-wise tree growth. Native categorical support. Best for >100K rows.

CatBoost

Best for categorical-heavy data with no encoding needed. Symmetric trees, minimal tuning. Strong default performance.

Section 04

Neural Networks & Deep Learning

Neural networks are universal function approximators composed of layers of learnable linear transformations followed by non-linear activations. Deep learning extends this to many layers, enabling hierarchical feature learning from raw data.

Forward Pass: Input x │ ├─► Layer 1: z₁ = W₁x + b₁, a₁ = ReLU(z₁) ├─► Layer 2: z₂ = W₂a₁ + b₂, a₂ = ReLU(z₂) └─► Output: ŷ = softmax(W₃a₂ + b₃) Backward Pass (Backpropagation): Loss L = CrossEntropy(y, ŷ) ∂L/∂W₃ → ∂L/∂W₂ → ∂L/∂W₁ (chain rule) Wᵢ := Wᵢ - α · ∂L/∂Wᵢ (gradient descent update)

Activation Functions

ActivationFormulaRangeUse CaseAvoid When
ReLUmax(0, x)[0, ∞)Hidden layers (default)Many dead neurons (>50% negative)
LeakyReLUmax(0.01x, x)(−∞, ∞)Fixes dying ReLU—
GELUx·Φ(x)(−∞, ∞)Transformers (BERT, GPT)—
Sigmoid1/(1+e⁻ˣ)(0, 1)Binary output layerHidden layers (vanishing gradient)
Softmaxeˣⁱ/Σeˣʲ(0, 1) summing to 1Multi-class output layerHidden layers
Tanh(eˣ−e⁻ˣ)/(eˣ+e⁻ˣ)(−1, 1)RNN hidden statesDeep networks (vanishing gradient)

Neural Network in PyTorch

import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

class MLP(nn.Module):
    def __init__(self, input_dim: int, hidden_dim: int, output_dim: int):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.BatchNorm1d(hidden_dim),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(hidden_dim, hidden_dim // 2),
            nn.ReLU(),
            nn.Linear(hidden_dim // 2, output_dim),
        )

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.net(x)

model = MLP(input_dim=128, hidden_dim=256, output_dim=10)
optimiser = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=1e-4)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimiser, T_max=50)
criterion = nn.CrossEntropyLoss()

# Training loop
for epoch in range(50):
    model.train()
    for X_batch, y_batch in train_loader:
        optimiser.zero_grad()
        loss = criterion(model(X_batch), y_batch)
        loss.backward()
        nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimiser.step()
    scheduler.step()

Key Deep Learning Concepts

Batch Normalisation Dropout Residual Connections Weight Initialisation Learning Rate Scheduling Gradient Clipping Attention Mechanism Transformer Architecture Transfer Learning Data Augmentation
The Transformer is a neural network too Every LLM is a deep neural network — specifically a decoder-only Transformer. Understanding backpropagation, attention, residual connections, and layer normalisation directly explains how GPT and Claude work at a mathematical level.
Section 05

Model Evaluation & Validation

A model is only as trustworthy as its evaluation methodology. Leaking test data into training — through improper splits, target encoding on the full set, or repeated test-set evaluation — produces optimistic estimates that don't hold in production.

Classification Metrics

MetricFormulaWhen to UsePitfall
Accuracycorrect / totalBalanced classes onlyMisleading on imbalanced data (99% negative → trivial classifier)
PrecisionTP / (TP + FP)False positives are costly (spam filter)Ignore recall — model predicts positive rarely
Recall (Sensitivity)TP / (TP + FN)False negatives are costly (cancer detection)Ignore precision — model predicts positive always
F1 Score2·P·R / (P+R)Need balance of precision & recallDoesn't account for true negatives
ROC-AUCArea under TPR vs FPR curveRanking quality, threshold-independentMisleading on severe class imbalance
PR-AUCArea under Precision vs RecallImbalanced classificationMore informative than ROC-AUC when positives are rare

Bias–Variance Trade-off

Total Error = Bias² + Variance + Irreducible Noise High Bias (Underfitting) High Variance (Overfitting) ───────────────────────── ────────────────────────── Model too simple Model too complex Train error: HIGH Train error: LOW Val error: HIGH Val error: HIGH Fix: more features, Fix: regularisation, dropout, more complex model more data, pruning

Cross-Validation & Hyperparameter Search

from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
import optuna

# Stratified K-Fold — preserves class ratios in each fold
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

def objective(trial):
    C     = trial.suggest_float("C", 1e-3, 100, log=True)
    gamma = trial.suggest_categorical("gamma", ["scale", "auto"])
    kernel = trial.suggest_categorical("kernel", ["rbf", "poly"])

    pipe = Pipeline([("sc", StandardScaler()),
                     ("svm", SVC(C=C, gamma=gamma, kernel=kernel))])

    scores = cross_validate(pipe, X_train, y_train, cv=cv,
                            scoring="roc_auc", n_jobs=-1)
    return scores["test_score"].mean()

study = optuna.create_study(direction="maximize")
study.optimize(objective, n_trials=50, timeout=120)
print(f"Best ROC-AUC: {study.best_value:.4f}")
print(f"Best params:  {study.best_params}")
Never tune on the test set Every time you peek at test-set performance and adjust your model, you are effectively training on it. Use a held-out test set exactly once — for the final reported number. Use validation or cross-validation for all tuning.
Section 06

Feature Engineering

Feature engineering — transforming raw input into representations that expose the signal the model needs — is the highest-leverage skill in applied ML. No algorithm automatically extracts domain knowledge from raw columns.

Numeric Features

import pandas as pd
import numpy as np
from sklearn.preprocessing import StandardScaler, PowerTransformer, KBinsDiscretizer

df = pd.DataFrame({"age": [23, 45, 67, 12], "income": [30000, 75000, 150000, 5000]})

# 1. Standardisation (mean=0, std=1) — required for linear/SVM/NN
scaler = StandardScaler()
df["age_scaled"] = scaler.fit_transform(df[["age"]])

# 2. Log transform — handles right-skewed distributions
df["log_income"] = np.log1p(df["income"])

# 3. Power transform (Yeo-Johnson) — makes distribution more Gaussian
pt = PowerTransformer(method="yeo-johnson")
df["income_normal"] = pt.fit_transform(df[["income"]])

# 4. Binning — captures non-linear age effects
binner = KBinsDiscretizer(n_bins=5, encode="ordinal", strategy="quantile")
df["age_bin"] = binner.fit_transform(df[["age"]])

Categorical Features

EncodingWhen to UseDimsNotes
One-Hot EncodingLow-cardinality nominal (<20 categories)+N colsCreates sparse matrix. Use drop="first" for linear models.
Label / OrdinalOrdered categories (low/mid/high)+1 colOnly valid when ordering is meaningful.
Target EncodingHigh-cardinality (city, user_id)+1 colCompute on train only; use CV to prevent leakage.
EmbeddingsVery high cardinality + NN model+k dimsLearned representations. Best quality but needs NN.
Frequency EncodingTree models + high cardinality+1 colReplace category with its count/frequency in train set.

Feature Selection

from sklearn.feature_selection import SelectFromModel, mutual_info_classif, RFE
from sklearn.ensemble import RandomForestClassifier

# Method 1: Tree-based feature importance
rf = RandomForestClassifier(n_estimators=100, random_state=42)
rf.fit(X_train, y_train)
selector = SelectFromModel(rf, threshold="median", prefit=True)
X_selected = selector.transform(X_train)

# Method 2: Mutual information (non-linear correlation with target)
mi_scores = mutual_info_classif(X_train, y_train)
top_features = X_train.columns[mi_scores.argsort()[::-1][:20]]

# Method 3: Recursive Feature Elimination
rfe = RFE(RandomForestClassifier(n_estimators=50), n_features_to_select=20)
rfe.fit(X_train, y_train)
Interaction features beat algorithm complexity Adding age × income or log(debt/income) often improves a linear model more than switching to XGBoost. Manual interaction features encode domain knowledge no algorithm can discover from sparse tabular data.
Section 07

Unsupervised Learning

Unsupervised learning discovers structure in data without labels. Its outputs — clusters, embeddings, and compressed representations — are often used as features for supervised models or as the basis for exploration and anomaly detection.

Clustering Algorithms

K-Means: 1. Randomly initialise K centroids 2. Assign each point to nearest centroid 3. Recompute centroids as cluster means 4. Repeat until convergence (O(n·k·i)) DBSCAN: Core point: has ≥ minPts neighbours within ε Clusters: connected components of core points Noise: points not reachable from any core point Advantage: finds arbitrary shapes, auto-detects K
AlgorithmK required?Cluster ShapeNoise handlingBest For
K-MeansYesSphericalNoLarge datasets, image segmentation, customer segments
DBSCANNoArbitraryYes (noise class)Spatial data, anomaly detection, unknown cluster count
Gaussian Mixture (GMM)YesEllipticalSoft assignmentOverlapping clusters, probabilistic membership
Hierarchical (Agglomerative)No (cut dendrogram)ArbitraryNoSmall datasets, when hierarchy matters

Dimensionality Reduction

from sklearn.decomposition import PCA
from sklearn.manifold import TSNE
import umap

# PCA — linear, preserves variance, interpretable components
pca = PCA(n_components=0.95)  # keep 95% of variance
X_pca = pca.fit_transform(X_scaled)
print(f"Reduced from {X.shape[1]} to {X_pca.shape[1]} dimensions")
print(f"Explained variance ratio: {pca.explained_variance_ratio_[:5]}")

# t-SNE — non-linear, excellent 2D visualisation, not for ML features
X_tsne = TSNE(n_components=2, perplexity=30, random_state=42).fit_transform(X_scaled)

# UMAP — non-linear, preserves global structure better than t-SNE, usable as ML features
reducer = umap.UMAP(n_components=16, random_state=42)
X_umap = reducer.fit_transform(X_scaled)  # use as features for downstream model
UMAP > t-SNE for features; t-SNE for visualisation t-SNE distorts global structure (only preserves local neighbourhoods). UMAP preserves both local and global structure and is fast enough to use as a feature transformation step before a classifier. Use t-SNE only for 2D plots.
Section 08

ML Pipelines with scikit-learn

scikit-learn's Pipeline and ColumnTransformer are the right way to build reproducible, leak-proof ML workflows. They chain preprocessing and modelling into a single object that can be cross-validated, serialised, and deployed atomically.

Full Production Pipeline

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder, PowerTransformer
from sklearn.impute import SimpleImputer
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.model_selection import cross_val_score
import joblib

numeric_features  = ["age", "income", "credit_score"]
categorical_features = ["employment_type", "region"]

# Preprocessing sub-pipelines
numeric_transformer = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),
    ("power",   PowerTransformer(method="yeo-johnson")),
    ("scaler",  StandardScaler()),
])

categorical_transformer = Pipeline([
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot",  OneHotEncoder(handle_unknown="ignore", sparse_output=False)),
])

preprocessor = ColumnTransformer([
    ("num", numeric_transformer,    numeric_features),
    ("cat", categorical_transformer, categorical_features),
])

# Full pipeline
full_pipeline = Pipeline([
    ("preprocessor", preprocessor),
    ("classifier",   GradientBoostingClassifier(
        n_estimators=300, learning_rate=0.05, max_depth=4,
        subsample=0.8, random_state=42
    )),
])

# Cross-validated evaluation (no leakage — transform fitted per fold)
scores = cross_val_score(full_pipeline, X, y, cv=5, scoring="roc_auc")
print(f"ROC-AUC: {scores.mean():.4f} ± {scores.std():.4f}")

# Train final model and save
full_pipeline.fit(X_train, y_train)
joblib.dump(full_pipeline, "model_v1.pkl")

# Load and predict (preprocessing automatically applied)
model = joblib.load("model_v1.pkl")
probas = model.predict_proba(X_new)[:, 1]

Scikit-learn Ecosystem

Pipeline

Chain transformers + estimator. Prevents leakage, enables cross-validation of entire workflow.

ColumnTransformer

Apply different preprocessing to numeric vs categorical columns in parallel.

GridSearchCV / RandomizedSearchCV

Hyperparameter search with built-in cross-validation. Use RandomizedSearchCV for >4 params.

joblib

Serialise trained pipelines to disk. Models are ~1MB–100MB. Always version with a hash of training data.

Section 09

ML → LLM Bridge

Large Language Models are built on the same mathematical foundations as classical ML — gradient descent, backpropagation, regularisation — but at trillion-parameter scale with the Transformer architecture. Understanding classical ML makes LLM engineering intuitive.

Classical ML Concept → LLM Equivalent ───────────────────────────────────────────────────── Gradient descent → Adam / AdamW optimiser Regularisation (L2) → Weight decay Dropout → Attention dropout Batch normalisation → Layer normalisation Feature extraction → Tokenisation + embeddings Transfer learning → Pre-trained base model Fine-tuning → SFT / LoRA / QLoRA Cross-validation → Eval set + RAGAS metrics Hyperparameter tuning → LR, batch size, rank (LoRA) Ensemble → Mixture of Experts (MoE) Logistic regression → Softmax output over vocabulary

Attention Is Just Weighted Feature Aggregation

Self-Attention for token xᵢ: 1. Compute query Qᵢ = Wq · xᵢ 2. Compute keys Kⱼ = Wk · xⱼ (for all tokens j) 3. Scores = softmax(QᵢKᵀ / √d) ← scaled dot product 4. Output = Σⱼ scores[j] · Vⱼ ← weighted average of values This is equivalent to: learn which features (other tokens) matter for predicting token xᵢ, then aggregate them. Same intuition as an attention-weighted feature mean in classical ML.

Key Connections

ML ConceptWhy It Matters for LLMs
Bias-variance trade-offLLMs overfit to fine-tuning data (high variance). LoRA rank controls capacity = bias-variance knob.
Class imbalanceLLM instruction datasets have imbalanced task types. Curating balanced datasets improves fine-tuning quality.
Feature importanceAttention weights ≈ feature importance. Attention visualisation helps debug why a model focuses on wrong context.
Data leakageTest documents in pre-training = data leakage. Benchmark contamination inflates LLM eval scores.
Learning rate schedulingWarmup + cosine decay is standard for LLM training. Too high LR → loss spikes. Too low → slow convergence.
Classical ML is not obsolete For structured tabular data — fraud detection, pricing models, churn prediction — XGBoost and LightGBM still outperform LLMs by a significant margin. LLMs excel at unstructured text; gradient-boosted trees excel at tabular numerical data.
