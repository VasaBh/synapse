3. Load Balancing Outside OpenShift (External)

External load balancers sit in front of the entire OpenShift cluster. They are the first point of contact for client traffic and distribute requests to the OpenShift worker nodes running router (ingress controller) pods, and to control plane nodes for API access.

3.1 External Hardware / Software Load Balancers

Enterprise environments commonly use dedicated load balancer appliances or software:

ProductTypeKey Features
F5 BIG-IPHardware/Virtual ApplianceLTM for local LB, GTM/DNS for GSLB. Native OpenShift integration via CIS (Container Ingress Services).
Citrix NetScalerHardware/Virtual ApplianceADC with GSLB capability via MEP. Supports active-active and active-passive.
HAProxyOpen Source SoftwareHigh-performance L4/L7 LB. The same software OpenShift uses internally for its router.
NGINXOpen Source / CommercialL7 reverse proxy and LB. NGINX Plus adds health checks, session persistence.
Keepalived + VIPsOpen Source (On-Prem IPI)Built into on-prem OpenShift IPI. Provides HA via VIPs but not true load distribution.

3.2 Cloud Provider Load Balancers

When OpenShift is installed via IPI (Installer Provisioned Infrastructure) on a cloud provider, the installer automatically provisions cloud-native load balancers:

  • AWS: Network Load Balancer (NLB) for the API (port 6443) and an Application Load Balancer or NLB for ingress (ports 80/443).
  • Azure: Azure Load Balancer for both API and ingress endpoints.
  • GCP: Google Cloud Load Balancer with TCP proxy for API and HTTP(S) LB for ingress.

These are automatically managed by the cloud provider and scaled dynamically. No manual configuration is required.

3.3 DNS-Based Load Balancing

The simplest external load balancing approach is DNS round-robin, where a hostname resolves to multiple IP addresses. The DNS server rotates the order of IPs in its response, and the client typically connects to the first IP.

Limitations: No health checking (clients may be sent to dead servers), relies on client-side TTL behaviour, no awareness of server load or capacity. Primarily used as a cheap supplementary mechanism, not as a primary load balancer.
