2. Horizontal Pod Autoscaler (HPA)

The HPA is built into OpenShift and Kubernetes. It periodically queries the metrics API (every 15 seconds by default), computes the ratio of current metric value to the target value, and adjusts the replica count of a Deployment, StatefulSet, or DeploymentConfig accordingly.

HPA Control Loop
+-------------+        +------------------+        +----------------+
|  Metrics    | -----> |  HPA Controller  | -----> | Deployment /   |
|  Server     |  CPU,  |  (every 15s)     | scale  | ReplicaSet     |
| (resource   |  Mem   |                  | up/down|                |
|  metrics)   |        |  desiredReplicas |        | replicas: N    |
+-------------+        |  = ceil(current  |        +----------------+
|  / target * cur) |
+------------------+

2.1 Supported Metrics

  • CPU Utilization: Percentage of requested CPU used. Most common. Works via oc autoscale command.
  • Memory Utilization: Percentage of requested memory used. Requires YAML definition (no CLI shortcut). Memory must decrease proportionally when replicas increase.

2.2 Prerequisites

Your pods MUST have resource requests defined. HPA computes utilisation as a percentage of the requested value. Without requests, HPA cannot calculate metrics and will not function.

# Pod spec with resource requests (REQUIRED for HPA)
containers:
- name: my-api
image: my-registry/my-api:latest
resources:
requests:
cpu: 200m        # HPA calculates: actual_cpu / 200m
memory: 256Mi    # HPA calculates: actual_mem / 256Mi
limits:
cpu: 1000m
memory: 512Mi

2.3 Example: CLI

# Scale between 2 and 10 pods, targeting 70% CPU utilisation
oc autoscale deployment/my-api --min=2 --max=10 --cpu-percent=70
# Check HPA status
oc get hpa
oc describe hpa my-api

2.4 Example: YAML (CPU + Memory)

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
name: my-api-hpa
spec:
scaleTargetRef:
apiVersion: apps/v1
kind: Deployment
name: my-api
minReplicas: 2
maxReplicas: 10
metrics:
- type: Resource
resource:
name: cpu
target:
type: Utilization
averageUtilization: 70
- type: Resource
resource:
name: memory
target:
type: Utilization
averageUtilization: 80
behavior:
scaleDown:
stabilizationWindowSeconds: 300    # Wait 5 min before scaling down
policies:
- type: Percent
value: 10
periodSeconds: 60              # Remove max 10% of pods per minute
scaleUp:
stabilizationWindowSeconds: 0
policies:
- type: Percent
value: 100
periodSeconds: 15              # Can double pods every 15s

Limitations: HPA only supports CPU and memory natively. It cannot scale to zero (minimum is 1 replica). It cannot scale on custom metrics like HTTP requests per second without an external adapter.
