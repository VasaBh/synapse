5. MCP – MODEL CONTEXT PROTOCOL

5.1 What is MCP?

MCP (Model Context Protocol) is an open standard created by Anthropic that defines how AI models connect to external tools, data sources, and services. It replaces ad-hoc tool integration with a standardised client-server architecture.

5.2 Architecture Overview

MCP ServerExposes tools, resources, prompts to the clientGitHub MCP, Slack MCP, custom DB server

5.3 Core Primitives

Resources

  • Expose data that the AI can read: files, database records, API responses
  • URI-addressable (e.g., file:///project/src, postgres://db/users)
  • Can be static or dynamically generated on request
  • Analogous to GET endpoints — read-only data exposure

Tools

  • Callable functions the AI can invoke to take actions
  • Each tool has a JSON Schema definition (name, description, input schema)
  • Examples: search_database, send_email, create_ticket, execute_query
  • The AI decides when and how to call tools based on context and user intent
  • Analogous to POST endpoints — side-effectful operations

Prompts

  • Reusable, parameterised prompt templates stored on the server
  • Allow server to define standard workflows (e.g., 'code review prompt', 'bug report template')
  • User can invoke named prompts; server fills in context automatically

Sampling

  • Allows MCP server to request LLM completions via the client
  • Enables agentic loops where the server itself needs AI reasoning
  • Server sends sampling/createMessage → client routes to LLM → result returned to server

5.5 Security Considerations (Architect-level)

  • Authentication – OAuth2 / API keys for remote servers; validate on every request
  • Authorisation – scope tool access per user/role; least privilege per session
  • Tool sandboxing – restrict what tools can access (filesystem, network, secrets)
  • Input validation – validate all tool arguments against JSON Schema before execution
  • Rate limiting – prevent AI from looping and hammering tools
  • Audit logging – log every tool call, arguments, and result for compliance
  • Prompt injection defence – validate that tool results don't contain malicious instructions
  • Human-in-the-loop – require approval before destructive/irreversible tool calls

5.7 Enterprise MCP Design Patterns

  • MCP Gateway – single entry point that routes to multiple MCP servers; centralises auth/logging
  • Tool Registry – catalogue of available tools with descriptions; dynamic tool discovery
  • Capability versioning – version your MCP server tools for backward compatibility
  • Caching layer – cache read-only resource responses to reduce downstream load
  • Async tools – for long-running operations, return a job ID and expose a status resource
💡 Interview Tip: Expected question: 'How would you design an MCP server for our internal knowledge base?' Answer: expose documents as Resources (URI-addressed), create Tools for semantic search and summarisation, add authentication via OAuth2, implement rate limiting, and audit-log every access.
