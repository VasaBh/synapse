Section 01

Advanced Language Features

Python's power comes from composable, expressive language features — closures, comprehensions, unpacking, type hints, and flexible function signatures that let you write concise, readable, and highly capable code.

*args and **kwargs

*args captures positional extras as a tuple; **kwargs captures keyword extras as a dict. Together they enable variadic APIs and decorator forwarding.

def log(level, *args, sep=" ", **meta):
    print(f"[{level}]", sep.join(str(a) for a in args), meta)

log("INFO", "user", "logged in", sep="-", user_id=42)
# [INFO] user-logged in {'user_id': 42}

Closures

A closure is a function that captures variables from its enclosing scope. The captured variables live in the function's __closure__ attribute as cells.

def make_multiplier(n):
    def multiply(x):
        return x * n   # n is a free variable — captured in closure
    return multiply

double = make_multiplier(2)
print(double(5))  # 10
print(double.__closure__[0].cell_contents)  # 2

Comprehensions

FormSyntaxReturns
List[expr for x in it if cond]list
Dict{k: v for k, v in it}dict
Set{expr for x in it}set
Generator(expr for x in it)generator (lazy)

Unpacking & Walrus Operator

first, *rest = [1, 2, 3, 4]      # first=1, rest=[2,3,4]
a, b = b, a                        # swap without temp variable

# Walrus := — assign and test in one expression
if (n := len(data)) > 10:
    print(f"Too long: {n} items")

Type Hints (Python 3.10+)

from typing import TypeVar, Generic

T = TypeVar("T")

def first(items: list[T]) -> T | None:
    return items[0] if items else None

# Union shorthand (3.10+)
def parse(value: int | str | None) -> str:
    return str(value) if value is not None else ""
Interview Tip Type hints are not enforced at runtime — they are annotations for static analysis tools (mypy, pyright) and documentation. Use from __future__ import annotations to defer evaluation and support forward references.
Section 02

Decorators

A decorator is a callable that takes a function (or class) and returns a replacement. They implement the wrapper pattern — adding behaviour before or after a function without modifying its source.

Anatomy of a Decorator

import functools

def my_decorator(func):
    @functools.wraps(func)          # preserves __name__, __doc__, etc.
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)
        print("after")
        return result
    return wrapper

@my_decorator
def greet(name):
    print(f"Hello, {name}")

# Equivalent to: greet = my_decorator(greet)
Always use @functools.wraps Without it, the wrapper hides the original function's __name__, __doc__, and __module__, breaking introspection, logging, and test frameworks.

Parameterised Decorators

def retry(times=3, exceptions=(Exception,)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    if attempt == times - 1:
                        raise
            return None
        return wrapper
    return decorator

@retry(times=5, exceptions=(ConnectionError,))
def fetch(url): ...

Class Decorators

class Singleton:
    def __init__(self, cls):
        self._cls = cls
        self._instance = None
        functools.update_wrapper(self, cls)

    def __call__(self, *args, **kwargs):
        if self._instance is None:
            self._instance = self._cls(*args, **kwargs)
        return self._instance

@Singleton
class Config:
    def __init__(self): self.debug = False

Built-in Decorators

@property

Turns a method into a read-only attribute. Pair with @x.setter for write access. Enables validation without changing the public API.

@staticmethod

No implicit first argument. Pure utility function scoped to the class namespace. Cannot access self or cls.

@classmethod

Receives cls (the class) as first argument. Used for alternative constructors: dict.fromkeys(), datetime.fromisoformat().

@functools.cache

Memoises a function (unbounded LRU). Use @functools.lru_cache(maxsize=128) for bounded caching. Thread-safe.

@dataclasses.dataclass

Auto-generates __init__, __repr__, __eq__, and optionally __hash__, __lt__, __slots__.

@abstractmethod

Marks a method as abstract in an ABC. Subclasses must implement it or they cannot be instantiated.

Section 03

Generators

A generator is a function that uses yield to produce values lazily, one at a time, suspending execution between calls. They enable memory-efficient iteration over potentially infinite sequences.

yield vs return

def countdown(n):
    while n > 0:
        yield n      # suspend here, return value to caller
        n -= 1       # resume here on next()

gen = countdown(3)
print(next(gen))   # 3
print(next(gen))   # 2
list(countdown(3)) # [3, 2, 1] — exhausts the generator

yield from

yield from delegates to a sub-generator, forwarding values, return values, and thrown exceptions — essential for generator composition.

def chain(*iterables):
    for it in iterables:
        yield from it       # equivalent to: for item in it: yield item

def flatten(nested):
    for item in nested:
        if isinstance(item, list):
            yield from flatten(item)
        else:
            yield item

send() and Two-Way Communication

def accumulator():
    total = 0
    while True:
        value = yield total   # yield sends total out, receives value in
        if value is None:
            break
        total += value

acc = accumulator()
next(acc)           # prime the generator (advance to first yield)
acc.send(10)        # 10
acc.send(20)        # 30

Memory Pattern Processing a 10 GB log file with a generator pipeline reads one line at a time — constant memory. With a list comprehension it would load the entire file into RAM.
Section 04

Async / Await

Python's async model is cooperative multitasking on a single thread via an event loop. It excels at I/O-bound concurrency — network calls, database queries, file I/O — where threads would mostly sleep.

Core Concepts

Coroutine

An async def function. Calling it returns a coroutine object — it doesn't execute until awaited or scheduled.

Event Loop

The scheduler that runs coroutines. Only one task runs at a time; tasks yield control at await points.

Task

asyncio.create_task(coro()) schedules a coroutine to run concurrently. Returns a Task (a Future subclass).

await

Suspends the current coroutine and gives control back to the event loop until the awaitable completes.

Patterns

import asyncio
import aiohttp

# Sequential — each waits for the previous
async def fetch_sequential(urls):
    async with aiohttp.ClientSession() as session:
        for url in urls:
            async with session.get(url) as resp:
                print(await resp.text())

# Concurrent — all fire simultaneously
async def fetch_concurrent(urls):
    async with aiohttp.ClientSession() as session:
        tasks = [session.get(url) for url in urls]
        responses = await asyncio.gather(*tasks)
        return [await r.text() for r in responses]

asyncio.run(fetch_concurrent(urls))

asyncio.gather vs asyncio.TaskGroup

asyncio.gatherasyncio.TaskGroup (3.11+)
Error handlingReturns exceptions or raises firstCancels all tasks on any failure
CancellationManualAutomatic structured concurrency
Return valueList of resultsAccess via task.result()
Use whenNeed all results, tolerate partial failureStructured concurrency, 3.11+

Common Pitfalls

Blocking the Event Loop Calling a blocking function (file I/O, requests, CPU work) inside a coroutine freezes all other tasks. Use asyncio.to_thread() or loop.run_in_executor() to offload to a thread pool. 
# Wrong — blocks the event loop
async def bad():
    data = open("file.txt").read()   # synchronous

# Correct — offload to thread pool
async def good():
    data = await asyncio.to_thread(open("file.txt").read)

# Or use aiofiles
import aiofiles
async def better():
    async with aiofiles.open("file.txt") as f:
        data = await f.read()
Section 05

Context Managers

Context managers implement the with statement protocol, guaranteeing setup and teardown regardless of exceptions — the canonical resource-management pattern in Python.

Protocol: __enter__ / __exit__

class DatabaseConnection:
    def __enter__(self):
        self.conn = connect_db()
        return self.conn          # bound to `as` target

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.conn.close()
        return False              # False = don't suppress exceptions
                                  # True  = suppress (swallow) exceptions

with DatabaseConnection() as conn:
    conn.execute("SELECT 1")

contextlib.contextmanager

Turns a generator into a context manager — everything before yield is the enter, everything after is the exit.

from contextlib import contextmanager

@contextmanager
def temp_directory():
    path = pathlib.Path(tempfile.mkdtemp())
    try:
        yield path                # __enter__ returns this
    finally:
        shutil.rmtree(path)       # __exit__ — always runs

with temp_directory() as tmp:
    (tmp / "data.csv").write_text("id,value\n1,42")

contextlib Utilities

UtilityPurpose
contextlib.suppress(*exc)Silently swallows listed exception types
contextlib.nullcontext(val)No-op context manager, useful in conditional with
contextlib.ExitStackDynamically compose multiple context managers
contextlib.redirect_stdoutRedirect stdout to a file-like object
contextlib.closing(obj)Calls obj.close() on exit
__exit__ return value Returning a truthy value from __exit__ suppresses the exception — the with block continues as if nothing happened. Almost always return False or None. Suppression is appropriate for contextlib.suppress-style helpers only.
Section 06

Async Context Managers

Async context managers extend the context manager protocol to work inside async def functions, supporting await in both setup and teardown phases.

Protocol: __aenter__ / __aexit__

class AsyncDBConnection:
    async def __aenter__(self):
        self.conn = await connect_db_async()
        return self.conn

    async def __aexit__(self, exc_type, exc_val, exc_tb):
        await self.conn.aclose()
        return False

async def main():
    async with AsyncDBConnection() as conn:
        await conn.execute("SELECT 1")

contextlib.asynccontextmanager

from contextlib import asynccontextmanager

@asynccontextmanager
async def managed_session(base_url: str):
    async with aiohttp.ClientSession(base_url) as session:
        try:
            yield session
        finally:
            pass  # ClientSession.__aexit__ handles cleanup

async def fetch():
    async with managed_session("https://api.example.com") as s:
        resp = await s.get("/data")
        return await resp.json()

Section 07

Async Generators & Their Uses

Async generators combine async def with yield, allowing lazy production of values that involve async operations — essential for streaming data from async sources.

Basic Async Generator

import asyncio

async def ticker(interval: float, count: int):
    for i in range(count):
        await asyncio.sleep(interval)
        yield i                          # suspends with yielded value

async def consume():
    async for tick in ticker(0.1, 5):   # async for iterates async generators
        print(f"Tick {tick}")

Streaming HTTP Responses

import aiohttp

async def stream_lines(url: str):
    async with aiohttp.ClientSession() as session:
        async with session.get(url) as resp:
            async for line in resp.content:
                yield line.decode().strip()

async def process():
    async for line in stream_lines("https://api.example.com/stream"):
        print(line)

map, reduce & Functional Programming

Python supports first-class functions, closures, and higher-order functions that enable a functional style. While not a pure functional language, Python's tools enable clean, composable data transformations.

map / filter / reduce

from functools import reduce

nums = [1, 2, 3, 4, 5]

squares    = list(map(lambda x: x**2, nums))         # [1, 4, 9, 16, 25]
evens      = list(filter(lambda x: x % 2 == 0, nums)) # [2, 4]
total      = reduce(lambda acc, x: acc + x, nums)     # 15

# Prefer comprehensions for readability
squares = [x**2 for x in nums]
evens   = [x for x in nums if x % 2 == 0]

lambda

Anonymous single-expression functions. Use for short callbacks; for anything complex, use a named function for readability.

data = [{"name": "Alice", "age": 30}, {"name": "Bob", "age": 25}]
sorted_data = sorted(data, key=lambda d: d["age"])

# operator module avoids lambdas in common patterns
from operator import attrgetter, itemgetter
sorted_data = sorted(data, key=itemgetter("age"))

Composition Pattern

from functools import reduce

def compose(*fns):
    """Compose functions right-to-left: compose(f, g)(x) == f(g(x))"""
    return reduce(lambda f, g: lambda *a, **kw: f(g(*a, **kw)), fns)

pipeline = compose(str.strip, str.lower, str.title)
pipeline("  hello world  ")  # "Hello World"

Dunder (Magic) Methods

Dunder methods (double-underscore methods) are the hooks Python uses to implement operator overloading, container protocols, context managers, and object lifecycle — making custom objects behave like built-ins.

Object Lifecycle

MethodCalled whenNotes
__new__(cls)Object creation (before __init__)Returns the new instance; needed for immutable types
__init__(self)Object initialisationReceives the already-created instance
__del__(self)Object garbage collectedUnreliable timing; avoid for critical cleanup

Representation

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):           # unambiguous; used in REPL, logs, repr()
        return f"Point({self.x!r}, {self.y!r})"

    def __str__(self):            # human-friendly; used by print(), str()
        return f"({self.x}, {self.y})"

    def __format__(self, spec):   # f"{p:.2f}" support
        return f"({self.x:{spec}}, {self.y:{spec}})"

Comparison & Hashing

from functools import total_ordering

@total_ordering   # derive all comparisons from __eq__ and one of __lt__/__gt__
class Version:
    def __init__(self, major, minor):
        self.major, self.minor = major, minor

    def __eq__(self, other):
        return (self.major, self.minor) == (other.major, other.minor)

    def __lt__(self, other):
        return (self.major, self.minor) < (other.major, other.minor)

    def __hash__(self):           # required if __eq__ is defined
        return hash((self.major, self.minor))

Duck Typing & Protocols

"If it walks like a duck and quacks like a duck, it's a duck." Python checks behaviour at runtime, not class hierarchy. Protocols formalise this with structural subtyping — statically checked without inheritance.

Duck Typing in Practice

# Any object with .write() works — no base class required
def save(file_like, data):
    file_like.write(data)       # duck-typed: file, StringIO, socket, mock

from io import StringIO
buf = StringIO()
save(buf, "hello")
print(buf.getvalue())  # hello

Abstract Base Classes (ABCs)

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float: ...

    @abstractmethod
    def perimeter(self) -> float: ...

    def describe(self):                 # concrete method on ABC
        return f"area={self.area():.2f}"

class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self): return 3.14159 * self.r ** 2
    def perimeter(self): return 2 * 3.14159 * self.r

# Shape()   → TypeError: Can't instantiate abstract class

typing.Protocol (Structural Subtyping)

from typing import Protocol, runtime_checkable

@runtime_checkable
class Drawable(Protocol):
    def draw(self) -> None: ...

class Circle:                   # no inheritance from Drawable
    def draw(self): print("○")

class Square:
    def draw(self): print("□")

def render(shape: Drawable):    # static type checker accepts any Drawable
    shape.draw()

isinstance(Circle(), Drawable)  # True — runtime check via @runtime_checkable

NumPy Broadcasting Rules

import numpy as np

a = np.array([[1, 2, 3]])    # shape (1, 3)
b = np.array([[1], [2], [3]])# shape (3, 1)
a + b                        # broadcasts to (3, 3)

# Rules: align shapes right-to-left; size-1 dims expand; mismatched non-1 dims → error
# (3,) + (3,)   → (3,)     ✓
# (1,3) + (3,1) → (3,3)    ✓
# (2,3) + (3,)  → (2,3)    ✓  (3,) treated as (1,3))
# (2,3) + (2,)  → Error    ✗

Metaprogramming

Metaprogramming means code that writes or modifies code. Python's data model — metaclasses, descriptors, __init_subclass__, and exec/eval — enables powerful frameworks like Django ORM, dataclasses, and Pydantic.

Metaclasses

A metaclass is the class of a class. type is the default metaclass for all classes. Metaclasses intercept class creation.

class SingletonMeta(type):
    _instances = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class Config(metaclass=SingletonMeta):
    def __init__(self): self.debug = False

Config() is Config()  # True

__init_subclass__ — Lightweight Plugin System

class Handler:
    _registry: dict[str, type] = {}

    def __init_subclass__(cls, name: str, **kwargs):
        super().__init_subclass__(**kwargs)
        Handler._registry[name] = cls

class JSONHandler(Handler, name="json"):
    def handle(self, data): return json.dumps(data)

class XMLHandler(Handler, name="xml"):
    def handle(self, data): return f"{data}"

Handler._registry["json"]().handle({"x": 1})  # '{"x": 1}'

Descriptors

Descriptors control attribute access on a class. property, classmethod, and staticmethod are all descriptors.

class Validated:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None: return self
        return obj.__dict__.get(self.name)

    def __set__(self, obj, value):
        if not isinstance(value, (int, float)):
            raise TypeError(f"{self.name} must be numeric")
        obj.__dict__[self.name] = value

class Product:
    price = Validated()     # descriptor instance assigned to class attr

exec / eval

Security Warning Never pass user-supplied strings to exec or eval — they execute arbitrary code. Use only with trusted, program-generated strings (e.g., code generators, ORMs). 
# eval — evaluate a single expression, returns a value
result = eval("2 ** 10")                       # 1024

# exec — execute statements, returns None
code = "def greet(name): return f'Hello {name}'"
namespace = {}
exec(code, namespace)
namespace["greet"]("World")                    # Hello World

Testing

Robust Python testing combines pytest's ergonomic fixture system, unittest.mock for isolation, and coverage tools to enforce quality. The testing pyramid applies: many unit tests, fewer integration tests, minimal E2E tests.

pytest Fundamentals

# test_math.py
def add(a, b): return a + b

def test_add_integers():
    assert add(2, 3) == 5

def test_add_floats():
    assert add(0.1, 0.2) == pytest.approx(0.3)  # float tolerance

def test_add_raises():
    with pytest.raises(TypeError):
        add("a", 1)

Fixtures

import pytest

@pytest.fixture
def db_session():
    session = create_test_session()
    yield session             # setup above, teardown below
    session.rollback()
    session.close()

@pytest.fixture(scope="module")   # shared across all tests in module
def test_config():
    return {"debug": True, "db": "sqlite:///:memory:"}

def test_create_user(db_session, test_config):
    user = User(name="Alice")
    db_session.add(user)
    db_session.flush()
    assert user.id is not None

Parametrize

@pytest.mark.parametrize("input,expected", [
    ("hello", "HELLO"),

Section 15

The GIL (Global Interpreter Lock)

The GIL is a mutex in CPython that allows only one thread to execute Python bytecode at a time. It simplifies CPython's memory management at the cost of true CPU parallelism for pure-Python multi-threaded programs.

Why the GIL Exists

CPython uses reference counting for memory management. Without a lock, concurrent threads could corrupt reference counts, causing memory leaks or premature object deallocation. The GIL is a single coarse-grained lock that prevents this without per-object locks.

What the GIL Does and Doesn't Block

ScenarioGIL ImpactSolution
CPU-bound work (Python loops)Threads don't parallelize — each thread must acquire GILmultiprocessing, ProcessPoolExecutor
I/O-bound work (network, files)GIL released while waiting for I/O — threads work finethreading, asyncio both work
NumPy / C extensionsGIL released during C-level computationthreading is fine for NumPy-heavy code
Subprocess callsGIL released — runs in separate processsubprocess works fine with threads

Concurrency Models Compared

ModelBest ForGIL impactMemory
threadingI/O-bound, simple concurrencyLimited for CPU-boundShared
multiprocessingCPU-bound parallelismNone — separate processesSeparate (copy-on-write)
asyncioHigh-concurrency I/ONone — single threadShared

Python 3.13 — GIL is Optional (PEP 703)

Free-threaded Python (3.13+) Python 3.13 ships an experimental no-GIL build (python3.13t). The GIL can be disabled with PYTHON_GIL=0. True multi-core parallelism is now possible in pure Python. C extensions must opt-in via Py_mod_gil = Py_MOD_GIL_NOT_USED. Not yet production-recommended — ecosystem compatibility is still maturing. 
# Check if running free-threaded Python
import sys
print(sys._is_gil_enabled())   # True (GIL on) / False (free-threaded)

# multiprocessing — bypasses GIL entirely
from multiprocessing import Pool

def cpu_task(n):
    return sum(range(n))

with Pool(4) as pool:           # 4 separate Python processes
    results = pool.map(cpu_task, [10**7] * 4)

# concurrent.futures — clean Future-based API
from concurrent.futures import ProcessPoolExecutor
with ProcessPoolExecutor(max_workers=4) as ex:
    futures = [ex.submit(cpu_task, 10**7) for _ in range(4)]
    results = [f.result() for f in futures]
