5. Cluster and Machine Autoscaler (Node Scaling)

While HPA, KEDA, and VPA scale at the pod level, the Cluster Autoscaler and Machine Autoscaler scale the underlying infrastructure by adding or removing worker nodes. They work together to ensure the cluster has enough capacity to schedule all pods.

Node Autoscaling Flow
HPA/KEDA creates more pods
|
v
Pods become 'Pending' (no node has capacity)
|
v
Cluster Autoscaler detects pending pods
|
v
Machine Autoscaler adds Machines to MachineSet
|
v
Cloud/vSphere provisions new VM
|
v
New worker node joins cluster
|
v
Pending pods get scheduled on new node
[Reverse: when nodes < 50% utilised for extended period,
Cluster Autoscaler drains and removes the node]

5.1 ClusterAutoscaler Example

apiVersion: autoscaling.openshift.io/v1
kind: ClusterAutoscaler
metadata:
name: default
spec:
podPriorityThreshold: -10
resourceLimits:
maxNodesTotal: 24
cores:
min: 8
max: 128
memory:
min: 4
max: 256
gpus:
- type: nvidia.com/gpu
min: 0
max: 16
scaleDown:
enabled: true
delayAfterAdd: 10m
delayAfterDelete: 5m
delayAfterFailure: 3m
unneededTime: 5m
utilizationThreshold: "0.4"     # Node below 40% = candidate for removal

5.2 MachineAutoscaler Example

apiVersion: autoscaling.openshift.io/v1beta1
kind: MachineAutoscaler
metadata:
name: worker-us-east-1a
namespace: openshift-machine-api
spec:
minReplicas: 2                    # Never go below 2 nodes
maxReplicas: 8                    # Never exceed 8 nodes
scaleTargetRef:
apiVersion: machine.openshift.io/v1beta1
kind: MachineSet
name: my-cluster-worker-us-east-1a

Limitation: Cluster Autoscaler only works where the Machine API is operational — IPI installations on AWS, Azure, GCP, vSphere, or OpenStack. It does NOT work on bare-metal UPI clusters or manually managed infrastructure.
