Section 01

Classes, Objects & Constructors

Every class has at least one instance constructor, may have exactly one static constructor, and the order those run in is a favorite whiteboard question.

Static constructor lifecycle

Type first referencedfirst instance created, or first static member accessed
CLR runs the static constructorguaranteed exactly once, thread-safe, no params/modifiers
Static fields fully initialized
Instance constructor runs (if this reference was a `new`)
public class ConfigCache
{
    private static readonly Dictionary<string, string> _values;

    static ConfigCache()                 // static constructor — no access modifier, no parameters
    {
        _values = LoadFromDisk();        // runs exactly once, before ANY static/instance member is touched
        Console.WriteLine("ConfigCache initialized");
    }

    public ConfigCache() { }             // ordinary instance constructor — runs every `new ConfigCache()`

    public static string Get(string key) => _values[key];
}
Why the CLR guarantees this You never need a manual double-checked-locking singleton pattern for one-time setup — the runtime itself serializes and deduplicates static constructor execution across threads, even under concurrent first access.

Constructor chaining

public class Employee
{
    public string Name { get; }
    public decimal Salary { get; }

    public Employee(string name) : this(name, 50_000m) { }     // chains to the constructor below

    public Employee(string name, decimal salary)
    {
        Name = name;
        Salary = salary;
    }
}

public class Manager : Employee
{
    public int TeamSize { get; }
    public Manager(string name, decimal salary, int teamSize)
        : base(name, salary)          // must run before the Manager constructor body
    {
        TeamSize = teamSize;
    }
}
Execution order for new Manager(...) Static constructors of both Employee and Manager (if not already run) → field initializers → base(...) constructor body (Employee) → Manager constructor body. Base always finishes before derived — you can rely on base state being ready in the derived constructor body.

{
    public static double Square(double x) => x * x;

Section 02

Interfaces & Abstract Classes

Two different abstraction tools with overlapping surface area — knowing precisely where they diverge (state, multiple inheritance, member accessibility) is what interviewers probe.

Combined hierarchy

IRefundableTask Refund(decimal amount);
abstract class PaymentMethodabstract Pay(); virtual Validate();
CreditCard : PaymentMethod, IRefundable
public interface IRefundable
{
    Task RefundAsync(decimal amount);
}

public abstract class PaymentMethod
{
    protected PaymentMethod(string ownerName) => OwnerName = ownerName; // abstract classes CAN have constructors —
    public string OwnerName { get; }                                   // just never invoked via `new PaymentMethod(...)`

    public abstract Task PayAsync(decimal amount);   // no body — every concrete subclass MUST implement it
    public virtual bool Validate() => !string.IsNullOrEmpty(OwnerName); // has a body — subclasses MAY override it
}

public sealed class CreditCard : PaymentMethod, IRefundable
{
    public CreditCard(string owner) : base(owner) { }

    public override Task PayAsync(decimal amount) => ChargeAsync(amount);
    public sealed override bool Validate() => base.Validate() && CardNumber.Length == 16; // "sealed override": stop the override chain here
    public Task RefundAsync(decimal amount) => IssueCreditAsync(amount);

    public string CardNumber { get; init; } = "";
}

Explicit interface implementation

Used when a class implements two interfaces with a colliding member name, or when you want a member accessible only through the interface, not the concrete type. 

public interface IEnglishGreeter { string Greet(); }
public interface IFrenchGreeter { string Greet(); }

public class Bilingual : IEnglishGreeter, IFrenchGreeter
{
    string IEnglishGreeter.Greet() => "Hello";   // explicit — only reachable via an IEnglishGreeter reference
    string IFrenchGreeter.Greet() => "Bonjour";
}

var b = new Bilingual();
// b.Greet();                          // COMPILE ERROR — ambiguous / not a public member of Bilingual
Console.WriteLine(((IEnglishGreeter)b).Greet());  // "Hello"
Console.WriteLine(((IFrenchGreeter)b).Greet());   // "Bonjour"

virtual / override / abstract / sealed — the full dispatch table

ModifierMeaning
virtualHas a default body; subclasses may (but don't have to) override it
abstractNo body at all; every non-abstract subclass is required to override it
overrideReplaces a base virtual/abstract member — participates in runtime dispatch
sealed overrideOverrides, but forbids any further overriding down the hierarchy — locks the implementation from this point on
new (member hiding)Declares an unrelated member that just happens to share a name — breaks polymorphism; almost always the wrong tool versus override

Interface vs abstract class — the decision

Choose an interface

When unrelated types need to prove one capability (IDisposable, IComparable<T>) and you need multiple such contracts on one type.

Choose an abstract class

When you have real shared state and behavior across a true is-a family, and single inheritance is an acceptable constraint.

Default interface methods

Since C# 8, interfaces can carry a default body — used to version a public interface without breaking existing implementers.

Section 03

Generics

Generics let a type or method be parameterized over a type without boxing (§ of the companion guide) and without duplicating code per concrete type — the JIT specializes the generic for each value-type argument and shares one specialization across all reference-type arguments.

Generic class & method

public class Repository<TEntity> where TEntity : class, IEntity, new()
{
    private readonly List<TEntity> _items = new();

    public void Add(TEntity item) => _items.Add(item);
    public TEntity? Find(int id) => _items.FirstOrDefault(i => i.Id == id);
    public TEntity CreateDefault() => new TEntity();   // only legal because of the `new()` constraint
}

public static T Max<T>(T a, T b) where T : IComparable<T>   // generic method, independent of any generic class
    => a.CompareTo(b) >= 0 ? a : b;

int bigger = Max(3, 7);              // type argument  inferred — no need to write Max<int>

Constraints, in full

ConstraintRestricts T to
where T : classAny reference type
where T : structAny non-nullable value type
where T : new()A type with an accessible public parameterless constructor — enables new T() inside the generic
where T : BaseTypeMust derive from (or be) BaseType
where T : ISomeInterfaceMust implement the interface — lets you call interface members on T
where T : notnullExcludes a nullable value or reference type (NRT-aware)
where T : unmanagedA value type with no reference-type fields anywhere in its layout — required for pointer/Span-heavy low-level code

Variance: in and out

out T (covariant)T only ever appears as a return type
IProducer<string> → IProducer<object>
in T (contravariant)T only ever appears as a parameter type
IConsumer<object> → IConsumer<string>
public interface IProducer<out T> { T Produce(); }
public interface IConsumer<in T>  { void Consume(T item); }

IProducer<object> p = GetProducer<string>();     // covariant widening — safe, T only comes OUT
IConsumer<string> c = GetConsumer<object>();     // contravariant widening — safe, T only goes IN
Why List<T> can't be variant List<T> both takes T in (Add) and returns it out (indexer getter), so it can be neither in nor out — the compiler enforces that a variant type parameter is only ever used in the safe position throughout the entire interface.
Section 04

Properties, Indexers & Operator Overloading

Syntax that lets a custom type read like a built-in one.

Indexers

public class Matrix
{
    private readonly double[,] _data;
    public Matrix(int rows, int cols) => _data = new double[rows, cols];

    public double this[int row, int col]        // indexer — the type itself becomes "array-like"
    {
        get => _data[row, col];
        set => _data[row, col] = value;
    }
}

var m = new Matrix(3, 3);
m[0, 0] = 1.0;
Console.WriteLine(m[0, 0]);

Operator overloading

public readonly struct Money : IEquatable<Money>
{
    public decimal Amount { get; }
    public string Currency { get; }
    public Money(decimal amount, string currency) { Amount = amount; Currency = currency; }

    public static Money operator +(Money a, Money b)
    {
        if (a.Currency != b.Currency) throw new InvalidOperationException("Currency mismatch");
        return new Money(a.Amount + b.Amount, a.Currency);
    }

    public static bool operator ==(Money a, Money b) => a.Equals(b);
    public static bool operator !=(Money a, Money b) => !a.Equals(b);
    public bool Equals(Money other) => Amount == other.Amount && Currency == other.Currency;
    public override bool Equals(object? obj) => obj is Money m && Equals(m);
    public override int GetHashCode() => HashCode.Combine(Amount, Currency);

    public static implicit operator decimal(Money m) => m.Amount;        // implicit — always safe, no data loss
    public static explicit operator Money(decimal d) => new(d, "USD");   // explicit — requires an explicit cast
}

Money total = new Money(10, "USD") + new Money(5, "USD"); // uses operator+
decimal raw = total;                    // implicit conversion
Money back = (Money)25.0m;              // explicit conversion — must write the cast
Overload ==? Overload GetHashCode too Whenever you override value equality (operator or Equals), you must also override GetHashCode consistently, or the type silently breaks inside Dictionary/HashSet lookups.
Section 05

Delegates, Events & Lambdas

A delegate is a type-safe function reference; an event is a delegate with publisher/ subscriber discipline built on top of it.

Multicast delegates

Multicast delegateinvocation list — an ordered array of method targets
Handler A
Handler B
Handler C
+= appends to the invocation list; -= removes. Invoking the delegate calls every target in order — if one throws, the rest never run and the exception propagates to the caller. 
Action<string> log = Console.WriteLine;
log += msg => File.AppendAllText("log.txt", msg);   // now a 2-target multicast delegate
log("hello");                                       // both targets run, in order

The event keyword

public class OrderProcessor
{
    public event EventHandler<OrderShippedEventArgs>? OrderShipped;   // publisher-only add/remove surface

    public void Ship(Order order)
    {
        // ship logic...
        OnOrderShipped(new OrderShippedEventArgs(order));
    }

    protected virtual void OnOrderShipped(OrderShippedEventArgs e) =>
        OrderShipped?.Invoke(this, e);      // null-conditional — safe when nobody has subscribed
}

public class OrderShippedEventArgs : EventArgs
{
    public Order Order { get; }
    public OrderShippedEventArgs(Order order) => Order = order;
}

// Subscriber:
processor.OrderShipped += (sender, e) => Console.WriteLine($"Shipped order {e.Order.Id}");
event vs a plain public delegate field A plain public Action OnDone; field lets any outside code overwrite the entire invocation list with =, or invoke it directly. event restricts outside code to only +=/-= — invocation and reassignment stay private to the declaring class. Always prefer event for a public API.

Lambda closures — the loop-capture trap

var actions = new List<Action>();
for (int i = 0; i < 3; i++)
{
    actions.Add(() => Console.WriteLine(i));   // captures the VARIABLE i, not its value at this iteration
}
foreach (var a in actions) a();
// Since C# 5, `for`/`foreach` loop variables are scoped PER ITERATION, so this correctly prints 0,1,2.
// Pre-C#5 `for` loops (and any manually shared captured variable) print 3,3,3 — the same captured reference.
Section 06

Pattern Matching, Tuples & Control Flow

Modern C# control flow leans heavily on pattern matching and tuples instead of chains of if/is/as.

Switch expressions & property patterns

decimal GetShippingCost(Order order) => order switch
{
    { Total: > 500 }                 => 0m,
    { IsExpress: true, Total: > 100} => 15m,
    { IsExpress: true }               => 25m,
    null                              => throw new ArgumentNullException(nameof(order)),
    _                                 => 5m
};

Tuples & deconstruction

(string Name, int Age) person = ("Alice", 30);         // named tuple literal
Console.WriteLine(person.Name);

var (name, age) = person;                              // deconstruction into separate variables

public readonly struct Point
{
    public double X { get; init; }
    public double Y { get; init; }
    public void Deconstruct(out double x, out double y) { x = X; y = Y; }  // enables custom-type deconstruction
}
var (x, y) = new Point { X = 1, Y = 2 };

ref / out / in parameters

ModifierMeaning
refPassed by reference; must be initialized before the call; callee can read and reassign it
outPassed by reference; need NOT be initialized before the call; callee is required to assign it before returning
inPassed by reference but read-only inside the callee — avoids copying a large struct while preventing mutation
 
bool TryParseOrder(string raw, out Order? order) { ... }   // classic Try-pattern using `out`

void Scale(in Matrix4x4 m) { /* m is read-only here, but wasn't copied to pass it */ }

Local functions vs lambdas

public int Fibonacci(int n)
{
    return Fib(n);

    int Fib(int k) => k <= 1 ? k : Fib(k - 1) + Fib(k - 2);  // local function — named, supports recursion cleanly,
}                                                              // zero delegate allocation unless it captures state
Local function vs lambda assigned to Func A local function compiles to a plain private method when it doesn't capture anything — no delegate allocation at all. A lambda stored in a Func/Action always allocates a delegate object (and a compiler-generated closure class if it captures variables). Prefer local functions for private recursive/helper logic; reserve lambdas for when you need to actually pass the behavior around as data.

params arrays

public static int Sum(params int[] numbers) => numbers.Sum();
Sum(1, 2, 3);            // caller doesn't need to build an array explicitly
Sum(new[] { 1, 2, 3 });  // also legal

The value-type and lightweight-data-shape tools, plus the immutable-DTO idiom records exist for.

Structs — value semantics recap

public readonly struct Vector2
{
    public double X { get; }
    public double Y { get; }
    public Vector2(double x, double y) { X = x; Y = y; }  // readonly struct — every field is immutable after construction

Enums & [Flags]

public enum OrderStatus { Pending, Shipped, Delivered, Cancelled }  // backed by int by default

[Flags]
public enum Permissions
{
    None = 0,
    Read = 1 << 0,
    Write = 1 << 1,
    Execute = 1 << 2,

var p = Permissions.Read | Permissions.Write;   // bitwise-combinable because of [Flags]

Exceptions & Nullable Types

Two different "absence"/"failure" mechanisms that are easy to conflate: exceptions for exceptional failure, nullable types for expected absence.

Custom exception hierarchy

public class DomainException : Exception
{
    public DomainException(string message) : base(message) { }
    public DomainException(string message, Exception inner) : base(message, inner) { }
}

public class InsufficientFundsException : DomainException
{
    public decimal Shortfall { get; }
    public InsufficientFundsException(decimal shortfall)
        : base($"Short by {shortfall:C}") => Shortfall = shortfall;
}

Nullable value types

int? maybeAge = null;
int age = maybeAge ?? 0;             // null-coalescing — default if null
maybeAge ??= 18;                     // null-coalescing assignment — only assigns if currently null
if (maybeAge is int a) { /* pattern-matched, non-null 'a' in scope */ }
int forced = maybeAge!.Value;        // '!' null-forgiving operator — "trust me, compiler", throws if actually null

Nullable reference types (NRT)

#nullable enable
public class Customer
{
    public string Name { get; set; } = "";   // non-nullable — compiler warns if not initialized
    public string? Notes { get; set; }       // explicitly nullable
}

string Greet(Customer? c) => c?.Name is { Length: > 0 } n ? $"Hi {n}" : "Hi stranger";
Compile-time only NRT annotations are purely static analysis — string is still nullable at the IL/runtime level. A deserialized payload or an unchecked cast can still hand you a null a non-nullable-annotated variable "promised" not to have.
Section 09

Iterators, yield & Custom Collections

yield lets you write a lazily-evaluated sequence as straight-line imperative code — the compiler builds the state machine for you.

foreach (var x in Range(1, 3))
MoveNext() called once per iterationmethod body resumes right after the last `yield return`
Only ONE item exists in memory at a time
public static IEnumerable<int> Range(int start, int count)
{
    for (int i = 0; i < count; i++)
    {
        yield return start + i;    // suspend here; resume on the next MoveNext() call
    }
}

public static IEnumerable<int> Naturals()   // an INFINITE sequence — safe only because it's lazy
{
    int n = 0;
    while (true) yield return n++;
}

foreach (var n in Naturals().Take(5)) Console.WriteLine(n);  // 0,1,2,3,4 — never hangs
Same deferred-execution idea as LINQ Every LINQ operator in the companion guide's §4 is itself implemented with iterator blocks like this — that's the actual mechanism behind "a LINQ query doesn't run until you enumerate it."

Implementing a custom collection

public class Playlist : IEnumerable<string>
{
    private readonly List<string> _tracks = new();
    public void Add(string track) => _tracks.Add(track);

    public IEnumerator<string> GetEnumerator()
    {
        foreach (var t in _tracks) yield return t;
    }
    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();  // non-generic version, explicit implementation
}

Async/Await Language Mechanics

Runtime scheduling behavior (thread pool, deadlocks, ConfigureAwait) is covered in the companion .NET guide's §5 — this section is about what the C# compiler itself generates for an async method.

What async desugars to

async Task<Order> GetOrderAsync(int id)
Compiler-generated struct implementingIAsyncStateMachine
MoveNext() — one state per `await`a switch over an int `_state` field
AsyncTaskMethodBuilderwires up the returned Task and its continuations

Each await becomes a branch in that state machine: the method captures its locals into the struct's fields, registers a continuation with the awaited task, and returns. When the awaited operation completes, MoveNext() is called again and execution resumes exactly where it left off — locals intact.

Async streams — IAsyncEnumerable<T>

public async IAsyncEnumerable<Order> StreamOrdersAsync(
    [EnumeratorCancellation] CancellationToken ct = default)
{
    await foreach (var row in _db.QueryStreamAsync(ct))   // await foreach — the producer side is also async
    {
        yield return MapToOrder(row);                     // combines yield (lazy) with await (async I/O)
    }
}

await foreach (var order in StreamOrdersAsync(ct))         // consumer pulls one at a time, awaiting each fetch
{
    Process(order);
}
Why this exists Before C# 8, you had to choose between IEnumerable<T> (lazy but synchronous — blocks a thread on I/O) or Task<List<T>> (async but must buffer the entire result set in memory first). IAsyncEnumerable<T> gives you both: lazy, streamed, AND non-blocking.

Task vs ValueTask at the language level

public ValueTask<int> GetCachedAsync(string key)
{
    if (_cache.TryGetValue(key, out var value))
        return new ValueTask<int>(value);      // synchronous path — no Task allocation at all
    return new ValueTask<int>(FetchAndCacheAsync(key)); // async path — wraps a real Task
}
The one rule that trips people up A ValueTask may only be awaited once, and never awaited after it has already completed and been consumed — unlike Task, which is safe to await repeatedly or store and check later. Treat a ValueTask as single-use.

Section 12

Tricky Interview Questions

Language-feature-specific questions — see the companion guide's §11 for runtime/ecosystem interview questions (GC, EF Core, Orleans, SignalR).

Q1. Why can't a static constructor take parameters, and how would you make static initialization configurable?

The CLR invokes a static constructor automatically on first type access — there's no call site to pass arguments from. To make one-time static setup configurable, read from environment/config inside the static constructor body itself, or move to a static factory method plus a lazily-assigned static readonly field so the "constructor" logic can accept explicit input.

Q2. A NuGet package bumps a public const int MaxRetries = 3; to 5. Consumers don't see the new value until they recompile — why?

const values are burned directly into the IL of every consuming assembly at compile time — the constant is inlined, not read from the defining assembly at runtime. Changing it in the library and shipping a new DLL does nothing for already- compiled consumers until they rebuild against the new version. This is exactly why public library constants that might change should be static readonly instead.

Q3. When would you reach for explicit interface implementation instead of a normal public method?

Two colliding member names across implemented interfaces (Q shown in §2), or you want a member to be part of the type's contract but not clutter its public "natural" API — for example, implementing IDisposable.Dispose() explicitly on a type that also exposes a more discoverable Close() method for typical callers.

Q4. What's actually different between where T : class and where T : struct at the IL/JIT level?

where T : struct lets the JIT generate a fully specialized native implementation per value type (no boxing, direct field layout). where T : class lets all reference-type instantiations share a single compiled implementation, since they're all just pointer-sized references under the hood — that's why generic code with reference type arguments doesn't bloat the assembly the way many different value-type instantiations can.

Q5. Why did looping variable capture behavior change between old-style for loops and C# 5+?

Prior to C# 5, a for loop's iteration variable was a single variable shared across every closure created in the loop body, so all captured lambdas saw its final value after the loop ended. From C# 5 onward, foreach (and later for-loop-adjacent patterns) scope a fresh variable per iteration, so each closure captures its own snapshot — the fix eliminated a very common accidental-bug class.

Q6. What's the memory/laziness difference between a yield return-based iterator and a method that returns a fully built List<T>?

The iterator holds only one element's worth of state in memory at a time and only computes the next value when MoveNext() is actually called — it can represent an infinite or expensive-to-fully-compute sequence safely. A method returning List<T> must materialize and hold every element before returning, which is simpler to reason about but forces full computation and full memory cost up front.

Q7. Why does IAsyncEnumerable<T> need its own await foreach syntax instead of reusing regular foreach?

Regular foreach calls a synchronous MoveNext(): bool. An async sequence needs to await the next element becoming available (e.g. the next network page hasn't arrived yet) without blocking the calling thread — so the compiler needs distinct syntax to know it should await each MoveNextAsync(): ValueTask<bool> call instead of calling it synchronously.

Q8. Why can't a Span<T> be stored as a field on a regular class, or captured in an async method's state machine?

Span<T> is a ref struct — a type the runtime guarantees lives only on the stack, so it can safely wrap stack-allocated memory (e.g. stackalloc) without the GC needing to track or relocate it. A class field lives on the heap, and an async method's locals get hoisted into a heap-allocated state machine object across await boundaries — both would require a ref struct to potentially outlive its stack frame, which the compiler forbids outright.

Q9. Give a real reason to mark an override as sealed rather than just leaving it open.

When a specific override enforces an invariant the class's correctness depends on (e.g. a validation override that must always run the exact base check plus one extra rule), sealing it prevents a future subclass from silently reintroducing a bug by overriding it again and forgetting to call base.Method(). It documents "this behavior is final" directly in the type system instead of in a comment.

Q10. An abstract class can declare a constructor — if it can never be instantiated directly, what's it for?

The constructor still runs — just only ever as part of a concrete subclass's base(...) chain. It's how an abstract class enforces that every subclass must supply certain required state (e.g. protected PaymentMethod(string owner) in §2) at construction time, the same way any base class constructor guarantees invariants for its subclasses.
