Section 01

When to Fine-tune

Fine-tuning is often the last resort, not the first step. Before committing to the cost and complexity of training, verify that prompting, RAG, and few-shot examples cannot close the performance gap. This section frames the decision tree that governs the right adaptation strategy for your use case.

Decision Tree: Which Adaptation Strategy?

Start: Application underperforms baseline — what do you need? | v Need domain-specific STYLE, TONE, or OUTPUT FORMAT? |-YES--> SFT (Supervised Fine-tuning) | Teach format, persona, structured output via examples | '-NO --> Need better ALIGNMENT / human preference adherence? |-YES--> DPO / RLHF | Train on chosen vs rejected preference pairs | '-NO --> Need up-to-date or domain FACTUAL KNOWLEDGE? |-YES--> RAG (NOT fine-tuning) | Retrieval is cheaper and always updateable | '-NO --> Need to reduce COST or LATENCY? |-YES--> Distillation or smaller model SFT '-NO --> Better prompts + few-shot examples

Adaptation Strategy Comparison

ApproachCostLatency ImpactData NeededWhen To Use
PromptingZeroBaselineNoneFirst thing to try. Good system prompts solve ~50% of adaptation tasks with no overhead.
RAGLow (infra)+50–200 msDocuments / corpusFactual grounding, up-to-date knowledge, auditability, compliance requirements.
Few-shotZero extra+context token cost5–50 examplesStyle and format transfer when examples fit the context window. Free but not persistent.
SFTMediumSame as base1K–100K samplesDomain style, structured output, instruction following that prompting cannot reliably achieve.
RLHFHighSame as base10K+ preference pairs + human annotatorsSafety alignment, nuanced human preferences, model deployed at massive scale.
The 80% Rule 80% of use cases are solved by RAG + good prompts. Fine-tune only when you have exhausted those options. Training requires data collection pipelines, compute budget, evaluation infrastructure, and ongoing maintenance. Start simple, measure carefully, and fine-tune only when the cost of not doing so is clear.

Section 02

PEFT & Adapters

Parameter-Efficient Fine-Tuning (PEFT) methods update only a small subset of model parameters — typically less than 1% — while keeping the base weights frozen. This dramatically reduces compute, GPU memory, and storage overhead compared with full fine-tuning, making fine-tuning accessible on consumer hardware.

Architecture: Frozen Base + Lightweight Adapters

+----------------------------------------------------------+ | Pre-trained Base Model (FROZEN weights) | | | | Token --> [Self-Attention] --> [FFN] --> ... | | Embeds | ^ | | v | | | +-----------+ | | | LoRA Adpt | <-- ONLY these weights train | | | W = W0 | | | | + B*A | A in R^(r x k) (rand init) | | | (rank r) | B in R^(d x r) (zero init) | | +-----------+ | | | | Base params: ~7 000 000 000 Trainable: ~5 000 000 | | Trainable fraction: < 0.1 % | +----------------------------------------------------------+

PEFT Method Comparison

LoRA0.1–1%Low90–95%General instruction tuning, chat, code. Default PEFT choice.
Prefix Tuning0.1–0.5%Very Low80–88%Adding task-specific soft prompts; no changes to the model weights at all.
Prompt Tuning<0.1%Minimal75–85%Ultra-light adaptation of large models (>10B); works well at scale.

Code: Attach LoRA to a Base Model (Hugging Face PEFT)

from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model, TaskType

# 1. Load base model in auto precision
model_id = "meta-llama/Meta-Llama-3-8B"
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype="auto",
    device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained(model_id)

# 2. Define LoRA configuration
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=16,                          # Low-rank dimension
    lora_alpha=32,                 # Scaling factor; effective scale = alpha/r = 2
    target_modules=[               # Attention projections + MLP (Llama-3)
        "q_proj", "v_proj", "k_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_dropout=0.05,
    bias="none",
)

# 3. Wrap with PEFT — base weights are automatically frozen
model = get_peft_model(model, lora_config)

# 4. Report trainable parameter count
model.print_trainable_parameters()
# trainable params: 20,185,088 || all params: 8,051,232,768 || trainable%: 0.2508%
LoRA Efficiency Insight LoRA trains less than 1% of parameters but consistently reaches 90%+ of full fine-tuning quality across standard benchmarks. An added production benefit: you can serve dozens of LoRA fine-tuned variants simultaneously from a single base model by swapping adapter weights at inference time — critical for multi-tenant SaaS deployments where each customer has a customized model.
Section 03

LoRA & QLoRA Deep Dive

LoRA decomposes the weight update matrix into two low-rank matrices, reducing trainable parameters by 100–10,000x. QLoRA extends this by storing the frozen base model in 4-bit NF4 quantization, enabling fine-tuning of 7B+ models on a single 24 GB consumer GPU.

LoRA Mathematics

Standard weight update (prohibitively expensive for large models): DeltaW in R^(d x k) -- full rank update, billions of floats LoRA low-rank approximation: W = W0 + B * A | | FROZEN base TRAINABLE low-rank matrices (NF4 in A in R^(r x k) initialized randomly QLoRA) B in R^(d x r) initialized to zero (so BA=0 at training start) rank r << min(d, k) e.g. r=16 vs d=k=4096 Output during forward pass: h = W0 * x + (B * A * x) * (alpha / r) ^^^^^^^^^^^^ scaling factor; alpha=32, r=16 => scale=2 QLoRA additional optimizations: (1) W0 stored in 4-bit NF4 (Normal Float 4) -- NF4 is information-theoretically optimal for normally distributed weights (2) Double quantization: quantize the NF4 block scales too (-0.37 GB/7B model) (3) W0 dequantized to bf16 only during the matrix multiplication (4) Paged optimizers: Adam states streamed to CPU RAM when GPU is near-OOM

Code: QLoRA Setup with bitsandbytes

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

# 4-bit NF4 quantization configuration
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",           # Normal Float 4 -- optimal for LLM weights

    bnb_4bit_use_double_quant=True,      # Quantize the quantization constants too
)

model = AutoModelForCausalLM.from_pretrained(
    "mistralai/Mistral-7B-v0.1",
    quantization_config=bnb_config,
    device_map="auto",                   # Spread across available GPUs/CPU
)
tokenizer = AutoTokenizer.from_pretrained("mistralai/Mistral-7B-v0.1")
tokenizer.pad_token = tokenizer.eos_token   # Required for Mistral / Llama

Section 04

Supervised Fine-tuning (SFT)

SFT trains the model to imitate a curated dataset of (instruction, response) pairs using standard next-token prediction cross-entropy loss, applied only to the assistant tokens. It is the foundation of every modern instruction-tuned model and the required first step before alignment techniques such as RLHF or DPO.

SFT Training Pipeline

Raw Dataset (conversations / instruction-response pairs) | v Apply Chat Template -------> Llama-3: <|begin_of_text|><|start_header_id|>... tokenizer.apply_ Mistral: [INST] ... [/INST] ... chat_template() ChatML: <|im_start|>system\n...<|im_end|> | v Mask user/system tokens (loss computed ONLY on assistant tokens) Optional: pack multiple short samples to fill context window (2-3x throughput) | v SFTTrainer (TRL) |-- Gradient flows through LoRA adapter matrices A, B |-- Base model weights W0 remain frozen (no gradient) '-- Optimizer: paged_adamw_8bit (reduces optimizer memory ~75%) | v Fine-tuned Model (base weights + LoRA adapters saved separately)

Code: Full SFT Training with TRL SFTTrainer

from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig
from trl import SFTTrainer, SFTConfig
import torch

# ---- Load model with QLoRA ----
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16, bnb_4bit_use_double_quant=True,
)
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B-Instruct",
    quantization_config=bnb_config, device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Meta-Llama-3-8B-Instruct")
tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "right"

# ---- Load dataset and apply chat template ----
dataset = load_dataset("HuggingFaceH4/ultrachat_200k", split="train_sft")

def format_chat(example):
    return {"text": tokenizer.apply_chat_template(
        example["messages"], tokenize=False, add_generation_prompt=False
    )}

dataset = dataset.map(format_chat, remove_columns=list(dataset.features))

# ---- LoRA config ----
peft_config = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05, bias="none",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    task_type="CAUSAL_LM",
)

# ---- Training config ----
training_args = SFTConfig(
    output_dir="./llama3-sft",
    num_train_epochs=2,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,        # Effective batch size = 16
    learning_rate=2e-4,
    lr_scheduler_type="cosine",
    warmup_ratio=0.05,
    fp16=False, bf16=True,
    logging_steps=10,
    save_strategy="epoch",
    evaluation_strategy="epoch",
    max_seq_length=2048,
    packing=True,                         # Sequence packing: 2-3x throughput
    dataset_text_field="text",
    report_to="wandb",
)

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=peft_config,
)
trainer.train()
trainer.save_model("./llama3-sft-final")

Section 05

RLHF — Reinforcement Learning from Human Feedback

RLHF is the technique that transformed GPT-3 into ChatGPT and trained early Claude models. It uses a reward model trained on human preference annotations and Proximal Policy Optimization (PPO) to update the language model policy while a KL divergence penalty prevents catastrophic reward hacking.

RLHF Three-Step Pipeline

STEP 1 — Supervised Fine-tuning Pre-trained LLM ---[curated instruction data]--> SFT Model (raw next-token prediction) (instruction-following baseline) STEP 2 — Reward Model Training SFT Model generates multiple responses to the same prompts Human annotators rank responses: response_A > response_B Reward Model (RM) trained with Bradley-Terry loss: L_RM = -log sigmoid( r(x, y_chosen) - r(x, y_rejected) ) STEP 3 — PPO with KL Penalty [Policy (SFT init)] --- generates response y --> [RM] --> reward r(x,y) | | |<------ PPO gradient update maximize: E[r] - beta*KL --| | KL(pi_policy || pi_reference) penalizes drift from SFT baseline typical beta: 0.05 -- 0.2 RESULT: Policy that maximizes human preference reward without drifting too far from the SFT baseline

RLHF Components & Challenges

ComponentPurposeKey Challenge
SFT ModelInstruction-following starting point for PPORLHF cannot compensate for a weak SFT baseline — quality here is critical.
Reward ModelPredicts human preference score for any (prompt, response) pairReward hacking: policy exploits RM blind spots, generating high-score nonsense.
PPO TrainerUpdates policy via proximal policy optimization clippingRequires 4 models in GPU memory simultaneously: policy, reference, RM, value head.
KL DivergenceRegularization preventing the policy drifting from SFT referenceToo high β under-fits human preferences. Too low β causes reward hacking.
Reference ModelFrozen SFT copy used for KL penalty computationMust remain in memory throughout PPO training — doubles model memory cost.

Code: TRL RewardTrainer & PPOTrainer

from trl import RewardTrainer, RewardConfig, PPOTrainer, PPOConfig
from trl import AutoModelForCausalLMWithValueHead
from transformers import AutoModelForSequenceClassification

# ---- STEP 2: Train Reward Model ----
reward_model = AutoModelForSequenceClassification.from_pretrained(
    "meta-llama/Meta-Llama-3-8B-Instruct",
    num_labels=1,           # Single scalar reward output
    torch_dtype="auto",
    device_map="auto",
)

reward_config = RewardConfig(
    output_dir="./reward-model",
    per_device_train_batch_size=4,
    num_train_epochs=1,
    learning_rate=1e-5,
    max_length=512,
    remove_unused_columns=False,
)

# Dataset format: {"chosen": "<full conversation>", "rejected": "<full conversation>"}
reward_trainer = RewardTrainer(
    model=reward_model,
    args=reward_config,
    train_dataset=preference_dataset,
    tokenizer=tokenizer,
)
reward_trainer.train()
reward_trainer.save_model("./reward-model-final")

# ---- STEP 3: PPO Fine-tuning ----
ppo_model = AutoModelForCausalLMWithValueHead.from_pretrained(
    "./llama3-sft-final", torch_dtype=torch.bfloat16, device_map="auto"
)
ref_model = AutoModelForCausalLMWithValueHead.from_pretrained(
    "./llama3-sft-final", torch_dtype=torch.bfloat16, device_map="auto"
)

ppo_config = PPOConfig(
    model_name="llama3-sft",
    learning_rate=1e-5,
    batch_size=16,
    mini_batch_size=4,
    kl_penalty="kl",
    init_kl_coef=0.2,
    target_kl=6.0,          # Adaptive KL controller target
    horizon=10000,
)

ppo_trainer = PPOTrainer(
    config=ppo_config, model=ppo_model,
    ref_model=ref_model, tokenizer=tokenizer,
)

for batch in ppo_trainer.dataloader:
    query_tensors = batch["input_ids"]
    # Generate responses from current policy
    response_tensors = ppo_trainer.generate(
        query_tensors, max_new_tokens=200, do_sample=True, temperature=0.7
    )
    # Score with reward model
    texts = tokenizer.batch_decode(response_tensors)
    rewards = [reward_model(t).logits.squeeze() for t in texts]
    # PPO gradient step
    stats = ppo_trainer.step(query_tensors, response_tensors, rewards)
    ppo_trainer.log_stats(stats, batch, rewards)
RLHF is Expensive and Unstable RLHF requires training and simultaneously serving 4 models (policy, reference, reward model, value head), collecting expensive human preference annotations, and careful tuning of the KL penalty coefficient to avoid reward hacking or policy collapse. DPO achieves comparable alignment quality without a reward model in a single supervised training pass on preference pairs — significantly cheaper, faster, and more stable. Prefer DPO unless you have strong reasons for online RL.
Section 06

DPO & ORPO

Direct Preference Optimization (DPO) reformulates the RLHF objective as a supervised loss over preference pairs, eliminating the reward model entirely. ORPO goes further by merging SFT and alignment into a single pass, reducing training time by ~40% versus the two-step SFT→DPO pipeline.

DPO: Preference Learning Without a Reward Model

Human Preference Dataset (same format as RLHF, no reward model needed): { "prompt": "Explain quantum computing", "chosen": "Quantum computers use qubits that can exist in superposition...", "rejected": "I am not sure about quantum computing, it is very complex." } | v DPO Loss -- derived analytically from the RLHF objective: L_DPO = -E [ log sigmoid( beta * log( pi_theta(y_w | x) / pi_ref(y_w | x) ) - beta * log( pi_theta(y_l | x) / pi_ref(y_l | x) ) ) ] y_w = chosen (winner response) pi_theta = policy being trained y_l = rejected (loser response) pi_ref = frozen reference (SFT) model beta = temperature param (0.1-0.5) Reference model provides an IMPLICIT reward signal via the log-ratio. No explicit reward model, no PPO loop, no value head. | v Updated policy: assigns higher probability to chosen over rejected responses

Code: TRL DPOTrainer — Full Example

from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer
from trl import DPOTrainer, DPOConfig
from peft import LoraConfig
import torch

# Load policy model and frozen reference model
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B-Instruct",
    torch_dtype=torch.bfloat16, device_map="auto",
)
ref_model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B-Instruct",
    torch_dtype=torch.bfloat16, device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Meta-Llama-3-8B-Instruct")
tokenizer.pad_token = tokenizer.eos_token

# Preference dataset: requires columns {prompt, chosen, rejected}
dataset = load_dataset("HuggingFaceH4/ultrafeedback_binarized", split="train_prefs")

peft_config = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05, bias="none",
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    task_type="CAUSAL_LM",
)

dpo_config = DPOConfig(
    output_dir="./llama3-dpo",
    beta=0.1,                        # DPO temperature; lower = tighter alignment
    num_train_epochs=1,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    learning_rate=5e-6,              # Lower than SFT -- fine adjustments only
    bf16=True,
    max_length=1024,
    max_prompt_length=512,
    logging_steps=10,
    save_strategy="epoch",
)

trainer = DPOTrainer(
    model=model,
    ref_model=ref_model,
    args=dpo_config,
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=peft_config,
)
trainer.train()
trainer.save_model("./llama3-dpo-final")

Benchmarks on Llama-3 and Mistral show ORPO matches DPO quality on MT-Bench and AlpacaEval.
Section 07

Dataset Curation

The quality of your fine-tuning dataset matters more than its size. A carefully curated 1K sample dataset consistently outperforms a noisy 100K dataset in both benchmark performance and generalization. This section covers deduplication, quality filtering, synthetic generation, and format standards.

Data Curation Pipeline

Raw Data (web scrapes, internal documents, licensed datasets) | v Deduplication |-- Exact match: SHA-256 hash of normalized text, discard duplicates '-- Near-duplicate: MinHash LSH (Jaccard similarity > 0.8 -> remove) | v Quality Filtering |-- Perplexity filter: score with small LM (GPT-2); drop PPL > threshold |-- Length filter: remove samples < 20 tokens or > 3x median length |-- LLM judge scoring: GPT-4o-mini rates instruction-response quality 1-5 |-- PII detection: spacy NER + Microsoft Presidio -> redact or remove '-- Toxicity filter: Perspective API or LlamaGuard <-> drop toxic content | v Format Standardisation |-- Apply target chat template (Llama-3 / ChatML / Alpaca) |-- Validate JSON schema; check for empty fields, truncated responses '-- Ensure consistent instruction quality across category buckets | v Train / Val / Test Split |-- 90% train / 5% validation / 5% held-out test '-- Stratified split by task category to ensure balanced evaluation

Code: Synthetic Data Generation with LLM Judge Quality Filter

import json, random
from openai import OpenAI

client = OpenAI()

# ---- Step 1: Self-instruct -- generate diverse instruction tasks ----
def generate_instructions(seed_tasks: list[str], n: int = 100) -> list[str]:
    sample = random.sample(seed_tasks, min(5, len(seed_tasks)))
    prompt = (
        f"Generate {n} diverse instruction tasks similar to these examples:\n"
        + "\n".join(f"- {t}" for t in sample)
        + "\n\nReturn a JSON object: {\"instructions\": [\"...\", ...]}"
    )
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
        response_format={"type": "json_object"},
    )
    return json.loads(resp.choices[0].message.content)["instructions"]

# ---- Step 2: Generate high-quality responses ----
def generate_response(instruction: str) -> str:
    resp = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "You are a helpful, accurate assistant."},
            {"role": "user",   "content": instruction},
        ],
        temperature=0.7,
    )
    return resp.choices[0].message.content

# ---- Step 3: LLM judge quality filter (1-5 scale) ----
JUDGE_PROMPT = """Rate the quality of this instruction-response pair on 1-5.
Criteria: helpfulness, accuracy, completeness, clarity.
Instruction: {instruction}
Response: {response}
Return JSON: {{"score": <int>, "reason": "<string>"}}"""

def quality_score(instruction: str, response: str) -> int:
    result = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": JUDGE_PROMPT.format(
            instruction=instruction, response=response
        )}],
        response_format={"type": "json_object"},
    )
    return json.loads(result.choices[0].message.content)["score"]

# ---- Pipeline: generate, filter, save ----
seed_tasks = ["Summarize a legal contract", "Write a Python sorting algorithm", ...]
dataset = []
for instr in generate_instructions(seed_tasks, n=500):
    resp = generate_response(instr)
    if quality_score(instr, resp) >= 4:     # Keep only 4+ quality
        dataset.append({"instruction": instr, "output": resp})

print(f"High-quality examples retained: {len(dataset)} / 500")

# Save as JSONL
with open("curated_dataset.jsonl", "w") as f:
    for row in dataset:
        f.write(json.dumps(row) + "\n")
Quality Over Quantity 1K high-quality, diverse examples often beats 100K noisy, repetitive ones. The LIMA paper (Less Is More for Alignment) demonstrated that 1,000 carefully selected examples could match InstructGPT trained on 52K samples on most benchmarks. Invest 80% of your effort in data curation tooling — it has the highest ROI of any fine-tuning component.
