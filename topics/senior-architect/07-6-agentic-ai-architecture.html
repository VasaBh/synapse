6. AGENTIC AI ARCHITECTURE

6.1 What is an AI Agent?

An AI agent is an autonomous system that perceives its environment, reasons about it, takes actions (often via tools), observes the results, and iterates until a goal is achieved — without step-by-step human instruction for each action.

The Agent Loop

  • Perceive – receive input (user message, observation from environment)
  • Reason – use LLM to plan next action (what tool to call, what to say)
  • Act – execute tool call / produce output
  • Observe – receive tool result / environment feedback
  • Iterate – repeat until goal achieved or stopping condition met

6.2 Core Reasoning Patterns

PatternDescriptionBest For
ReActInterleave Reasoning and Acting; chain of thought drives tool selectionGeneral-purpose agents
Plan & ExecuteSeparate planning step from execution; planner creates task listComplex multi-step tasks
ReflexionAgent critiques its own output and retries with self-feedbackQuality-critical tasks
Tree of ThoughtExplore multiple reasoning branches; backtrack from dead endsComplex problem solving

6.3 Multi-Agent Architectures

Orchestrator–Subagent

  • Central orchestrator decomposes task and delegates to specialist subagents
  • Subagents: ResearchAgent, WritingAgent, CodeAgent, ValidationAgent
  • Orchestrator aggregates results and handles failures/retries
  • Analogous to a project manager delegating to a team

Peer-to-Peer (Swarm)

  • Agents communicate directly without central coordinator
  • Emergent behaviour from inter-agent negotiation
  • Harder to debug and control; risk of circular dependencies

Pipeline / DAG

  • Agents arranged in a directed acyclic graph
  • Output of one agent feeds into the next
  • Deterministic; easy to observe and test
  • Frameworks: LangGraph (graph-based), Prefect/Airflow (workflow DAGs)

6.5 Key Design Challenges

Safety & Control

  • Minimal footprint – request only necessary permissions; avoid storing sensitive data
  • Prefer reversible over irreversible actions (draft before send; stage before deploy)
  • Human-in-the-loop checkpoints – pause before destructive or high-value actions
  • Confirmation gates – 'Are you sure you want to delete 500 records?' before proceeding
  • Scope limiting – define clear boundaries; agent should refuse out-of-scope actions

Reliability

  • Idempotency – tool calls may be retried; ensure same call twice = same result
  • Error recovery – agent should recognise failure and replan, not loop infinitely
  • Timeouts – every tool call must have a maximum wait time
  • Max iteration limit – prevent infinite agent loops; set a hard cap

Observability

  • Trace every step of the agent loop (which tool, which arguments, which result)
  • Structured audit logs for compliance and debugging
  • Replay capability – re-run a failed agent run with same state for debugging

Security

  • Prompt injection – malicious content in tool results can hijack agent behaviour
  • Tool access control – agent should only have tools relevant to current task
  • Data exfiltration – prevent agent from sending sensitive data to external endpoints
  • Sandboxed code execution – if agent runs code, isolate in container/VM

6.7 Agentic AI + MCP Integration

  • MCP provides the standardised tool layer for agents to interact with external systems
  • Agent (LLM) uses MCP client to discover available tools and resources at runtime
  • Agent selects and calls tools via MCP protocol; receives structured results
  • MCP Sampling allows the MCP server itself to trigger AI reasoning (meta-agents)
  • Result: clean separation between AI reasoning logic and tool implementation
💡 Interview Tip: Expected question: 'How do you prevent an agent from taking destructive actions?' Answer: Human-in-the-loop gates for irreversible actions, prefer reversible actions, scope-limited tools, rate limiting, audit logging, and confirmation prompts before high-impact operations.
