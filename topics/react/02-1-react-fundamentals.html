1. React Fundamentals

1.1 What is React?

React is a JavaScript library (not a framework) created by Facebook (Meta) in 2013 for building user interfaces. It focuses exclusively on the View layer of an application.

Key Characteristics

  • Declarative: You describe WHAT the UI should look like, React handles HOW to update the DOM.
  • Component-Based: UI is divided into small, reusable, isolated pieces called components.
  • Unidirectional Data Flow: Data flows from parent to child via props, making the app predictable and easier to debug.

Example

// Declarative — just describe the UI
function Welcome({ name }) {
return <h1>Hello, {name}!</h1>;
}
// React figures out how to update the DOM efficiently

1.2 What is JSX?

JSX (JavaScript XML) is a syntax extension that lets you write HTML-like code inside JavaScript. It is NOT valid JavaScript — Babel transpiles it into React.createElement() calls.

JSX to JavaScript Transformation

// What you write (JSX):
const el = <h1 className="title">Hello</h1>;
// What Babel compiles it to:
const el = React.createElement('h1', { className: 'title' }, 'Hello');

Rules of JSX

  • Must return a single root element (use <> Fragment if needed)
  • Use className instead of class
  • Use camelCase for attributes: onClick, onChange
  • JavaScript expressions go inside {curly braces}
  • Self-close tags: <img />, <br />

1.3 Components: Functional vs Class

Functional Components (Modern — use these)

function Counter() {
const [count, setCount] = useState(0);
return (
<button onClick={() => setCount(count + 1)}>
Clicked {count} times
</button>
);
}

Class Components (Legacy — know for interviews)

class Counter extends React.Component {
state = { count: 0 };
render() {
return (
<button onClick={() =>
this.setState({ count: this.state.count + 1 })}>
Clicked {this.state.count} times
</button>
);
}
}
✅ Why Functional Components Won Simpler syntax, hooks for state/effects, easier to test, no ‘this’ binding issues, better performance with React Compiler.

1.4 Props vs State

FeaturePropsState
OwnerParent componentComponent itself
Mutable?❌ Read-only✅ Can update via setter
DirectionParent → ChildInternal
Re-render?When parent re-rendersWhen setState is called
function Parent() {
const [user, setUser] = useState("Alice"); // STATE
return <Child name={user} />;               // PROP
}
function Child({ name }) {
// 'name' is a PROP — cannot modify it
return <p>Hello, {name}</p>;
}
Golden Rule If data changes over time and affects rendering, it’s state. If it’s received from a parent, it’s a prop.

1.5 Conditional Rendering & Lists

React uses plain JavaScript for conditional rendering — no special template syntax:

function Dashboard({ isLoggedIn, isAdmin, notifications }) {
if (!isLoggedIn) return <LoginPage />;
return (
<div>
{isAdmin ? <AdminPanel /> : <UserPanel />}
{notifications.length > 0 && <Badge count={notifications.length} />}
</div>
);
}
⚠️ Gotcha with && Operator Avoid {count && <Component />}. If count = 0, it renders “0” on screen. Use {count > 0 && <Component />} instead.

Lists and Keys

function TodoList({ todos }) {
return (
<ul>
{todos.map(todo => (
<li key={todo.id}>{todo.text}</li>  // ✅ Unique, stable ID
))}
</ul>
);
}
// ❌ NEVER use index as key if list can reorder
// ❌ NEVER use Math.random() as key
