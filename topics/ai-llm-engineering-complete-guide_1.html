Section 01

LLM Engineering Fundamentals

A Large Language Model (LLM) is a deep neural network based on the Transformer architecture that predicts the next token in a sequence. Modern LLMs are decoder-only architectures trained via self-supervised learning and refined through RLHF or Constitutional AI.

Core Concepts

ConceptDescription
TokensUnits LLMs process. ~¾ of a word. "engineering" = 2 tokens. Vocabularies: 32K–256K tokens.
Context WindowTotal tokens the model sees at once: system prompt + history + documents + query. GPT-5.4: 270K–1.05M, Claude: 200K, Gemini 2.5: 2M.
TemperatureRandomness control. 0 = deterministic. 0.7 = balanced. 1.0+ = creative. Lower for code/facts.
EmbeddingsDense vector representations capturing semantic meaning. Used for similarity search, clustering, RAG. Dimensions: 256–3072.
AttentionCore Transformer mechanism. Every token attends to every other (n² relationships). Enables long-range dependencies.
InferenceTwo phases: Prefill (process input in parallel) and Decode (generate output token-by-token autoregressively).
Top-P / Top-KSampling strategies. Top-P (nucleus): smallest token set with cumulative prob ≥ P. Top-K: K highest-probability tokens.
Fine-tuningFurther training on domain data. Expensive. Alternatives: RAG (cheaper) or prompt engineering (cheapest).

Key API Parameters

model

Which model to use (gpt-5.4, claude-sonnet-4-20250514)

messages

Array of conversation messages with roles (system, user, assistant)

max_tokens

Maximum tokens the model can generate in response

temperature

Randomness control (0–2). Use 0 for deterministic tasks.

tools

Array of tool/function schemas the model can call

stream

If true, response tokens streamed as generated via SSE

Lost-in-the-Middle Problem LLMs perform best on information at the beginning and end of the context window, with degraded attention to content in the middle. All models tested showed accuracy drops past certain context thresholds — how you structure context matters as much as what you include.

client = OpenAI()

Section 05

RAG (Retrieval-Augmented Generation)

RAG connects LLMs to private enterprise data. It retrieves relevant documents from your knowledge base and injects them as context before generation — eliminating hallucinations and knowledge cutoff issues.

User Query → Embed Query → Vector Search (Top-K) → Retrieve Chunks → Augment Prompt → LLM Generates Grounded Answer

Chunking Strategies

StrategyHow It WorksBest For
Fixed-sizeSplit every N tokens/chars with overlap (e.g., 512 tokens, 50 overlap)Simple, predictable. Good starting point.
RecursiveTry splitting by paragraph → sentence → word. Falls through hierarchy.Most common. Good general-purpose.
SemanticSplit at topic boundaries detected by embedding similarity.Highest quality. ~9% recall improvement.
Document-awareSplit respecting headings, sections, tables, code blocks.Technical docs, legal contracts, papers.

Embedding Models

ModelDimensionsProviderNotes
text-embedding-3-small1536OpenAIBest cost/performance ratio. $0.02/1M tokens.
text-embedding-3-large3072OpenAIHighest quality from OpenAI.
voyage-3-large1024Voyage AIOutperforms OpenAI by 9–20%.
all-MiniLM-L6-v2384Open sourceFree, fast. Good for prototyping.

Advanced RAG Patterns

Query Transformation

Rewrite/expand queries before retrieval for better matching.

Hybrid Search

Combine dense vectors + BM25 keyword. Fuse with Reciprocal Rank Fusion.

Re-ranking

Re-score results with cross-encoder (Cohere Rerank) for higher precision.

GraphRAG

Combine knowledge graphs with vector retrieval for relationship reasoning.

Agentic RAG

Agent decides when/what to retrieve. Multi-step retrieval + self-correction.

Contextual Retrieval

Add doc-level context to each chunk before embedding (Anthropic technique).

Agentic AI

An AI Agent is an LLM that can reason, decide which tools to use, execute actions, observe results, and iterate. Multi-agent workflows grew 327% in the second half of 2025.

User Input → [THINK] Reason about task → [DECIDE] Choose tools → [ACT] Execute tool → [OBSERVE] Process results → REPEAT or RESPOND

Section 07

LangChain & LangGraph

LangChain provides abstractions for models, prompts, chains, agents, memory, and retrieval. LangGraph extends it with graph-based stateful agent orchestration.

Core Components

Models

Wrappers for OpenAI, Anthropic, HuggingFace, Ollama, Bedrock, 50+ providers.

Chains (LCEL)

Sequential pipelines: prompt → LLM → output parser. Composable via pipe operator.

Agents

LLMs that dynamically decide which tools to use. ReAct and function-calling agents.

Memory

Buffer, Summary, VectorStore memory for persistent multi-turn context.

Retrievers

VectorStore, MultiQuery, ContextualCompression, Ensemble retrievers.

LangSmith

Observability: tracing, debugging, evaluating LLM applications in production.

Example: RAG Chain

from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain.chains import RetrievalQA

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma(embedding_function=embeddings, persist_directory="./db")
retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

qa_chain = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-5.4", temperature=0),
    retriever=retriever,
    return_source_documents=True,
)
result = qa_chain.invoke({"query": "What is our refund policy?"})
Adoption Note 45% of developers who experimented with LangChain never deployed to production, and 23% eventually removed it. Many teams are moving to lighter alternatives: direct SDK calls, LiteLLM, or provider-specific SDKs. Evaluate whether the abstraction layer is needed for your use case.
Section 08

LiteLLM

The go-to open-source proxy for teams unifying access across 100+ LLM providers with an OpenAI-compatible interface. Run as a Python SDK or as a standalone proxy server (API gateway for LLMs).

Key Features

Unified API

Same completion() call works with all providers. Swap model string only.

Proxy Server

Run as API gateway. Your app talks to one endpoint; LiteLLM routes.

Load Balancing

Distribute across providers. Round-robin, least-busy routing.

Fallback Routing

If provider fails/rate-limited, auto-retry another.

Cost Tracking

Track spend per user/team/key. Budget limits.

Caching

Redis or in-memory. Reduce repeated API calls.

SDK Usage

from litellm import completion

# Same interface, any provider
resp = completion(
    model="gpt-5.4",
    messages=[{"role":"user",
               "content":"Hello"}])

resp = completion(
    model="claude-sonnet-4-20250514",
    messages=[{"role":"user",
               "content":"Hello"}])

resp = completion(
    model="ollama/llama3.1",
    messages=[{"role":"user",
               "content":"Hello"}])

Model Context Protocol (MCP)

The open standard (Anthropic, Nov 2024) that standardises how AI systems integrate with external tools. Called "USB-C for AI" — turns the N×M integration problem into N+M. Now governed by the Linux Foundation (AAIF).

HOST (Claude Desktop / ChatGPT / Cursor) ┌─────────┬─────────┬─────────┐ │Client 1 │Client 2 │Client 3 │ └────┬────┘────┬────┘────┬────┘ │stdio │HTTP/SSE │stdio ▼ ▼ ▼ ┌────────┐┌────────┐┌────────┐ │ GitHub ││Postgres││ Slack │ │ Server ││ Server ││ Server │ └────────┘└────────┘└────────┘

Three Primitives

Tools

Actions the model invokes. Similar to function calling but standardised and discoverable at runtime.

Resources

Read-only context. Like GET endpoints. Files, DB records, API responses. No side effects.

Prompts

Reusable templates the server exposes. "Summarise this PR", "Review this SQL query".

MCP vs Function Calling

AspectFunction CallingMCP
ScopeSingle provider's API featureCross-provider open standard
DiscoveryApp hardcodes schemas in API callClient discovers tools dynamically at runtime
OwnershipVendor-specific (each provider has own format)Linux Foundation / AAIF
PortabilityBuild once per providerBuild once, all MCP clients can use it
CapabilitiesTools onlyTools + Resources + Prompts

Adoption Timeline

Nov 2024: Anthropic launches Mar 2025: OpenAI adopts Apr 2025: Google DeepMind Nov 2025: Spec update Dec 2025: Linux Foundation Mar 2026: 97M monthly downloads

Example: MCP Server (Python)

from mcp.server import Server
from mcp.types import Tool, TextContent

server = Server("weather-server")

@server.list_tools()
async def list_tools():
    return [Tool(
        name="get_weather",
        description="Get weather for a city",
        inputSchema={
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"]
        }
    )]

@server.call_tool()
async def call_tool(name: str, arguments: dict):
    if name == "get_weather":
        return [TextContent(type="text",
            text=f"Weather in {arguments['city']}: 18°C")]

Prompt Engineering

The discipline of designing inputs that guide LLMs toward accurate, relevant outputs. 58 catalogued techniques as of 2025 — here are the essential ones.

TechniqueHow It WorksWhen to Use
Zero-ShotTask with no examples. Relies on pre-trained knowledge.Simple tasks, classification, Q&A.
Few-Shot2–5 examples before the task. Model learns the pattern.When output format/tone matters.
Chain-of-Thought"Think step by step." Explicit reasoning before answering.Math, logic, multi-step, debugging.
Role / Persona"You are a senior K8s architect." Shapes expertise + tone.Domain-specific tasks.
Self-ConsistencyMultiple reasoning paths, majority answer.High-stakes decisions.
Prompt ChainingBreak into sub-prompts. Output feeds next input.Multi-step: research → outline → draft.
ReActAlternate reasoning + action (tool calls). Agent foundation.Agentic tasks with tool use.
Meta-PromptingAsk model to generate/improve its own prompt.Prompt optimisation.

System Prompt Best Practices

  • Be specific: Define role, task, constraints, output format explicitly.
  • Use delimiters: XML tags, triple backticks, markdown headers to separate context from instructions.
  • Positive instructions: "Do X" rather than "Don't do Y". Models follow positive framing better.
  • Output format: Specify exactly: JSON, markdown, bullets, table. Use structured outputs for programmatic use.
  • Examples: Include 1–3 input/output pairs showing desired behaviour.
  • Temperature: 0 for deterministic/factual. 0.7–1.0 for creative/brainstorming.

Example: Production System Prompt

system = """
You are a senior cloud infrastructure advisor for a Fortune 500 company.

## Role
- Expert guidance on OpenShift, Kubernetes, cloud architecture
- Always cite specific tools, commands, or YAML when relevant
- If unsure, say so rather than guessing

## Output Format
- Markdown headers for sections
- Code blocks with language tags
- Max 500 words unless asked otherwise

## Constraints
- Do NOT recommend deprecated/EOL software
- Always mention security implications
- Assume production environment unless told otherwise
"""

Request Flow

  1. User sends a natural language query through the client application
  2. LiteLLM gateway routes to optimal LLM provider (cost, latency, fallback rules)
  3. Agent framework receives query, parses intent, decides: answer directly / retrieve context / call tools
  4. If RAG needed: embed query → search vector DB → retrieve top-K chunks → inject as context
  5. If tools needed: agent calls MCP servers (GitHub, Slack, DB, etc.) via JSON-RPC 2.0
  6. Memory reads/writes conversation history and session state for multi-turn context
  7. LLM generates grounded response using retrieved context + tool results + history
  8. Response streamed back (SSE) to user through the application with source citations

6 · Analytics use casesWhat the platform answers▶

Seasonality Analysis

Decomposes multi-year price history into trend + seasonal + residual (STL). The agent fetches 5+ years of daily data, runs seasonal_decompose(), and generates an overlay chart showing typical monthly patterns.

price_history("Brent",2019,2024) → seasonal_decompose(method="STL") → chart: monthly avg overlay → LLM: "Brent shows consistent Q1 weakness and Q4 strength..."

Realized Volatility Surface

Computes rolling realized vol at multiple windows (10d, 21d, 63d, 126d, 252d). Outputs a vol surface heatmap. Compares current implied vol vs realized to flag expensive/cheap options.

price_history("WTI",2020,2024) → calc_realized_vol(windows=[10,21,63,126,252]) → chart: heatmap + term structure → LLM: "Current 30d realized (28%) vs implied (34%) — skew suggests..."

Backtesting

Simulates a trading strategy over historical data. Agent takes strategy parameters, runs against OHLCV, returns P&L curve, Sharpe ratio, max drawdown, win rate.

parse_strategy("mean reversion, 2σ, 21d MA") → price_history("TTF Gas",2018,2024) → run_backtest(strategy, data) → chart: equity curve + drawdown → LLM: "Sharpe 1.42, max DD -18%, win rate 58%, best year 2022..."

Value at Risk (VaR)

Computes portfolio VaR using historical simulation or parametric method. Fetches positions, retrieves historical returns, computes correlation matrix, outputs VaR at 95%/99% with component breakdown.

get_portfolio("energy_desk") → price_history([instruments], 2yr) → compute_var(method="historical", confidence=[0.95,0.99]) → chart: VaR breakdown by instrument → LLM: "1-day 99% VaR is $2.4M, largest contributor is WTI..."
