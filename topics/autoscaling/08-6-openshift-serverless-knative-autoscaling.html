6. OpenShift Serverless (Knative) Autoscaling

Knative Serving, available via the OpenShift Serverless Operator, provides the most traffic-aware autoscaling. It uses an activator proxy that sits in the request path and directly counts concurrent requests or requests per second — no application-side metrics instrumentation is needed.

|
v
+------------------+
| Knative Activator|   <-- Counts concurrent requests
| (queue-proxy)    |   <-- Buffers if pods = 0
+--------+---------+
|
+-------+--------+

+---+   +---+   +---+

| 1 |   | 2 |   | 3 |
+---+   +---+   +---+

150 concurrent requests -> 3 pods
0   concurrent requests -> 0 pods (scale to zero)

6.1 Scaling Metrics

  • Concurrency (default): Number of simultaneous in-flight requests per pod. Target is 100 by default. When actual concurrency exceeds target, new pods are added.
  • RPS (Requests Per Second): Alternative metric. Scales based on throughput rather than concurrent connections.

6.2 Concurrency Limits

  • Soft limit (target): The desired number of concurrent requests per pod. Autoscaler tries to maintain this level but can briefly exceed it during bursts.
  • Hard limit (containerConcurrency): Absolute maximum concurrent requests per pod. Excess requests are queued/buffered.

6.3 Example: Knative Service with Autoscaling

apiVersion: serving.knative.dev/v1
kind: Service
metadata:
name: my-api
spec:
template:
metadata:
annotations:
autoscaling.knative.dev/target: "50"             # 50 concurrent requests/pod
autoscaling.knative.dev/min-scale: "0"           # Scale to zero when idle
autoscaling.knative.dev/max-scale: "20"          # Max 20 pods
autoscaling.knative.dev/scale-down-delay: "5m"   # Wait 5 min before scale down
autoscaling.knative.dev/target-utilization-percentage: "70"
spec:
containerConcurrency: 100     # Hard limit: buffer above 100
containers:
- image: my-registry/my-api:latest
ports:
- containerPort: 8000
resources:
requests:
cpu: 200m
memory: 256Mi

Key advantage: Your FastAPI application needs ZERO code changes. Knative handles all traffic counting externally via its queue-proxy sidecar.
