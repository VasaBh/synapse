3. How React Works Internally

3.1 Virtual DOM & Reconciliation

The Problem: Direct DOM manipulation is slow. Every update triggers layout recalculation, repainting, and compositing.

React’s Solution — Virtual DOM

  • Step 1: Component renders → Creates a Virtual DOM tree (plain JS objects).
  • Step 2: State changes → Creates a NEW Virtual DOM tree.
  • Step 3: React DIFFs old tree vs new tree (Reconciliation).
  • Step 4: React applies ONLY the minimal changes to the real DOM.

What a Virtual DOM Node Looks Like

// <div className="card"><h1>Hello</h1></div> becomes:
{
type: 'div',
props: { className: 'card' },
children: [{
type: 'h1',
props: {},
children: ['Hello']
}]
}

Reconciliation Rules

  • Different element types → tear down old tree, build new one.
  • Same element type → keep node, update changed attributes only.
  • Lists → use key prop to match old/new items efficiently.

3.2 React Fiber Architecture

Before Fiber (React ≤15): Reconciliation was SYNCHRONOUS. A large update blocked the main thread — UI froze, animations janked, inputs lagged.

Fiber (React 16+): Rewrote reconciliation as an INCREMENTAL, interruptible process. Each component becomes a “Fiber node” — a unit of work that React can pause between.

Two Phases

  • Render Phase (interruptible): React builds the new fiber tree and diffs it. Can be paused/restarted. No side effects.
  • Commit Phase (synchronous): React applies changes to the DOM in one go. Cannot be interrupted.
Priority System React assigns priority: User input > Animations > Data fetching > Offscreen updates. High-priority updates are processed first, keeping the UI responsive.

3.3 Batching & Concurrent Features (React 18+)

Automatic Batching: React 18 groups multiple state updates into a single re-render, even inside setTimeout, promises, and native event handlers.

useTransition — Mark Updates as Non-Urgent

const [isPending, startTransition] = useTransition();
const onChange = (e) => {
setQuery(e.target.value);           // Urgent: update input immediately
startTransition(() => {
setResults(filterData(e.target.value)); // Non-urgent: can be interrupted
});
};

useDeferredValue — Defer Expensive Rendering

const deferredText = useDeferredValue(text);
return <ExpensiveList filter={deferredText} />;
