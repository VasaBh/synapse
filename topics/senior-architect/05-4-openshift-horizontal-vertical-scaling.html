4. OPENSHIFT – HORIZONTAL & VERTICAL SCALING

4.1 Horizontal Scaling (Scale Out/In)

Adds or removes pod replicas to distribute load across more instances.

HPA – Horizontal Pod Autoscaler

  • Watches metrics server; compares current vs target utilisation
  • Scales pods up when: current / target > 1.0; scales down when: current / target < 1.0
  • Default metric: CPU utilisation (target 50–80% is common)
  • Custom metrics: Kafka consumer lag, queue depth, RPS via Prometheus Adapter
  • Key settings: minReplicas, maxReplicas, scaleUp / scaleDown stabilization windows
⚠️ Key Concept: Stabilization window prevents 'flapping'. Default scale-down stabilization is 300 seconds — pods don't disappear immediately after load drops.

KEDA – Kubernetes Event-Driven Autoscaler

  • Extends HPA; scales based on event source metrics
  • Supports 50+ scalers: Kafka, RabbitMQ, Azure Service Bus, SQS, Cron schedule
  • Scale-to-zero capability – ideal for batch jobs and queue consumers
  • Works by creating HPA objects under the hood; fully Kubernetes-native

Cluster Autoscaler (Node-level Scaling)

  • Adds nodes when pods are Pending due to insufficient resources
  • Removes underutilised nodes after configurable idle period
  • Works with MachineSets in OpenShift (cloud-provider aware)
  • Pod Disruption Budgets (PDB) protect minimum available pods during node drain

4.2 Vertical Scaling (Scale Up/Down)

Increases or decreases CPU and memory allocated to existing pods.

VPA – Vertical Pod Autoscaler

VPA ModeBehaviourUse Case
OffGenerates recommendations only; no action takenCapacity planning; tuning guidance
InitialSets resources at pod creation time onlyRight-size new pods without restarts
AutoEvicts and restarts pods with new resource valuesAutomated right-sizing (causes restarts)
RecreateSame as Auto but more aggressive evictionStateless workloads only

Resource Requests vs Limits

PropertyRequestLimit
DefinitionGuaranteed minimum reservedHard ceiling – cannot exceed
Scheduler useUsed to place pod on nodeNot used for scheduling
CPU breachN/ACPU throttled (not killed)
Memory breachN/AOOMKilled – container restarted
Best practiceSet based on average loadSet based on peak load + buffer

LimitRange & ResourceQuota

  • LimitRange – namespace-level defaults for requests/limits per pod/container
  • ResourceQuota – caps total CPU/memory/object count per namespace
  • Without LimitRange, containers with no limits can starve other pods on the node

4.3 HPA vs VPA – Decision Guide

Workload TypeRecommended ScalerReason
Stateless APIs / web servicesHPASafely add replicas; no state to migrate
Traffic spike scenariosHPA + KEDAFast scale-out triggered by queue depth or RPS
Stateful databases, singletonsVPA (Off/Initial)Can't simply add replicas; tune resources instead
Memory-bound ML inferenceVPAMore memory needed, not more copies
Event-driven batch jobsKEDAScale-to-zero between job runs
Mixed workloadHPA + VPA(Off)HPA scales pods; VPA gives resource recommendations
⚠️ Key Concept: Do NOT use HPA and VPA (Auto/Recreate mode) on the same CPU/memory metric simultaneously. Use VPA in 'Off' mode alongside HPA — it gives recommendations without conflicting with HPA's decisions.

4.4 OpenShift-Specific: MachineSets & MachineAutoscaler

  • MachineSet – declarative definition of a group of nodes (cloud-provider aware: AWS, GCP, Azure)
  • MachineAutoscaler – automatically adjusts MachineSet replica count based on cluster demand
  • ClusterAutoscaler – coordinates multiple MachineAutoscalers; defines cluster-wide min/max nodes
  • More powerful than vanilla K8s node autoscaling — integrates with cloud APIs directly

4.5 Key CLI Commands

Horizontal Scaling

  • oc scale deployment my-app --replicas=5 # manual scale
  • oc get hpa # list all HPAs
  • oc describe hpa my-app-hpa # current metrics vs target
  • oc autoscale deployment my-app --min=2 --max=10 --cpu-percent=70

Vertical / Node Scaling

  • oc describe vpa my-app-vpa # VPA recommendations
  • oc get machines -n openshift-machine-api # list machines
  • oc get machineautoscaler -n openshift-machine-api # list autoscalers
💡 Interview Tip: Interview answer for 'How do you prevent cascading failure during a traffic spike?' — HPA scales pods + Cluster Autoscaler adds nodes + PDB keeps minimum pods available + Circuit Breaker stops cascade. Layer your defences.
