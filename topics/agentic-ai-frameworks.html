Section 01

What Makes an Agent

An AI agent is a system that perceives its environment, maintains memory, reasons using an LLM, and takes actions via tools — looping until the task is complete. Unlike a simple pipeline, an agent can decide its own control flow at runtime.

The Agent Loop

Perceptionuser input · tool results
Memoryshort-term + long-term store
Reasoning (LLM)ReAct · CoT · function calls
Observeparse result · loop or finish
Actiontool call · code exec · API
placeholder
Tools
web_search() run_python() query_db() send_email()

Core Agent Capabilities

ReAct Loop

Reason then Act then Observe — interleaves chain-of-thought reasoning with tool executions. Transparent and debuggable.

Tool Use

Agent calls external tools (APIs, code execution, search) and feeds results back into context for further reasoning.

Memory

Short-term (in-context), long-term (vector store), episodic (event log). Enables multi-turn and cross-session continuity.

Planning

Decomposes complex goals into subtasks. Can use chain-of-thought, tree-of-thought, or LLM-driven task graphs.

Multi-step Execution

Runs multiple tool calls across multiple turns to achieve a goal that cannot be solved in a single LLM call.

Self-correction

Detects errors in tool output or reasoning, then retries with a corrected approach without human intervention.

Pipeline vs Agent

PropertyPipeline (Deterministic)Agent (Dynamic)
Control flowFixed, predefined steps known at build timeLLM decides steps dynamically at runtime
LatencyPredictable and boundedVariable — depends on loop count and tool calls
CostLow and boundedHigher and potentially unbounded — can spiral
ReliabilityHigh — same output for same inputLower — non-deterministic by nature
FlexibilityLow — cannot handle novel execution pathsHigh — adapts to unexpected situations
Best forKnown, structured tasks with clear stepsOpen-ended tasks where steps are not known upfront
Agents are Non-Deterministic — Always Add Human-in-the-Loop Agents are non-deterministic — always add human-in-the-loop checkpoints for high-stakes actions such as sending emails, modifying databases, executing financial transactions, or running arbitrary code. Build explicit escalation paths and approval gates before you deploy to production.

LangChain

LangChain provides composable abstractions for LLM applications. The modern API — LangChain Expression Language (LCEL) — uses a pipe operator to chain Runnables, enabling streaming, batching, and async execution out of the box with a single consistent interface.

LCEL Chain Anatomy

Input string or dict
RunnablePassthrough
passes input through, optionally renamed or merged
PromptTemplate
formats variables into a prompt string / message list
ChatOpenAI
calls the LLM, returns an AIMessage object
StrOutputParser
extracts .content string from the AIMessage
Output string

Example: LCEL RAG Chain

from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# Build vector store retriever
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma(embedding_function=embeddings, persist_directory="./db")
retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

# Build prompt template
template = """Answer the question using only the context below.

Context:
{context}

Question: {question}"""
prompt = ChatPromptTemplate.from_template(template)

# Helper to join retrieved docs
def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

# Compose LCEL chain: retriever | prompt | llm | parser
llm = ChatOpenAI(model="gpt-4o", temperature=0)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | llm
    | StrOutputParser()
)

# Invoke
answer = rag_chain.invoke("What is our refund policy?")
print(answer)

# Stream token-by-token
for chunk in rag_chain.stream("Explain the return window."):
    print(chunk, end="", flush=True)

Example: Tool-Calling Agent with AgentExecutor

from langchain_openai import ChatOpenAI
from langchain.agents import AgentExecutor, create_tool_calling_agent
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.tools import tool

@tool
def get_word_count(text: str) -> int:
    """Returns the number of words in the provided text string."""
    return len(text.split())

@tool
def web_search(query: str) -> str:
    """Searches the web and returns a summary of the top results."""
    # In production: integrate Tavily, SerpAPI, or Brave Search
    return f"Top results for: {query}"

tools = [get_word_count, web_search]

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant. Use tools when needed."),
    ("user", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

llm = ChatOpenAI(model="gpt-4o", temperature=0)
agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True, max_iterations=10)

result = executor.invoke({"input": "How many words are in the Gettysburg Address?"})
print(result["output"])

LangGraph

LangGraph extends LangChain with a graph-based stateful agent framework. Nodes are Python functions; edges define control flow including cycles; a shared TypedDict state threads through every node. This enables complex, long-running, resumable, and multi-agent workflows with full persistence.

StateGraph Control Flow

START
agent_node
calls LLM with bound tools; decides next action
should_
continue?
yes — tool_calls
tool_nodeexecutes tool calls
loops back to agent
no — done
respond_nodewrites final answer
END

Example: LangGraph StateGraph Agent

from typing import TypedDict, Annotated, Sequence
from langgraph.graph import StateGraph, START, END
from langgraph.prebuilt import ToolNode
from langchain_openai import ChatOpenAI
from langchain_core.messages import BaseMessage, HumanMessage
from langchain_core.tools import tool
import operator

# 1. Shared typed state
class AgentState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], operator.add]

# 2. Tools
@tool
def web_search(query: str) -> str:
    """Search the web for up-to-date information on a topic."""
    return f"Search results for '{query}': [simulated results here]"

tools = [web_search]
tool_node = ToolNode(tools)

# 3. LLM with tools bound
llm = ChatOpenAI(model="gpt-4o", temperature=0).bind_tools(tools)

def agent_node(state: AgentState) -> AgentState:
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

def should_continue(state: AgentState) -> str:
    last = state["messages"][-1]
    if hasattr(last, "tool_calls") and last.tool_calls:
        return "tools"
    return "end"

# 4. Build and compile graph
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tool_node)

graph.add_edge(START, "agent")
graph.add_conditional_edges(
    "agent",
    should_continue,
    {"tools": "tools", "end": END}
)
graph.add_edge("tools", "agent")   # cycle back after tool execution

app = graph.compile()

# 5. Run
result = app.invoke({"messages": [HumanMessage(content="Latest news on AI agent frameworks?")]})
print(result["messages"][-1].content)

Example: Checkpointing and Human-in-the-Loop

from langgraph.checkpoint.memory import MemorySaver

# Dev: MemorySaver (in-process)
# Prod: PostgresSaver or RedisSaver for durable persistence
checkpointer = MemorySaver()

app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=["tools"]   # pause before every tool execution
)

# Thread config — identifies the conversation
config = {"configurable": {"thread_id": "session-42"}}

# First run — will pause when it reaches the tool node
for event in app.stream(
    {"messages": [HumanMessage(content="Delete all temp files in /workspace")]},
    config=config,
    stream_mode="values",
):
    print(event["messages"][-1])

# Inspect pending state before approving
state = app.get_state(config)
print("Waiting at:", state.next)    # ('tools',)

# Human reviews tool calls and approves — pass None to resume
for event in app.stream(None, config=config, stream_mode="values"):
    print(event["messages"][-1])
LangGraph Persistence Enables Long-Running, Resumable Workflows LangGraph's checkpointing (MemorySaver, PostgresSaver, RedisSaver) serialises the entire graph state after every node transition. This enables workflows that span hours or days, survive server restarts, support human review and approval gates, and allow time-travel debugging by replaying from any prior checkpoint. It is the key architectural advantage over simpler agentic frameworks.

LangGraph Concepts

ConceptDescription
StateA TypedDict shared across all nodes. Reducers (e.g., operator.add) control how list fields are merged on update.
NodeA Python function (or Runnable) that receives the current state and returns a partial state update dict.
EdgeDirects control flow from one named node to another. Can be unconditional (always fires) or conditional.
Conditional EdgeA router function that inspects state and returns a string key mapping to the next node — enables branching and loops.
CheckpointerPersists full graph state after every node transition. Enables resumability, human-in-the-loop, and audit trails.
Interruptinterrupt_before or interrupt_after pauses graph execution at a named node so an external process can inspect and resume.

CrewAI

CrewAI models agent collaboration as a "crew" of specialists. Each agent has a role, goal, and backstory. Tasks are assigned and flow through sequential or hierarchical processes. The intuitive, role-based API makes it the fastest framework to prototype multi-agent content pipelines.

CrewAI Architecture

task_1 (researcher)
task_2 (writer)
Processsequential · hierarchical
Output

Example: Sequential Pipeline with Two Agents

from crewai import Agent, Task, Crew, Process
from crewai_tools import SerperDevTool

search_tool = SerperDevTool()

# Define specialist agents
researcher = Agent(
    role="Senior Research Analyst",
    goal="Uncover cutting-edge developments in AI agent frameworks for 2026",
    backstory=(
        "You work at a leading AI research lab. Your in-depth analysis and "
        "benchmarks directly inform the company's technology roadmap."
    ),
    tools=[search_tool],
    verbose=True,
    max_iter=5,
)

writer = Agent(
    role="Technical Content Writer",
    goal="Write clear, engaging comparison articles for software developers",
    backstory=(
        "You specialise in translating complex AI research into actionable "
        "developer guides with concrete code examples."
    ),
    verbose=True,
)

# Define tasks
research_task = Task(
    description=(
        "Research the latest releases, benchmarks, and community adoption of "
        "LangGraph, CrewAI, AutoGen, and Pydantic AI as of 2026."
    ),
    expected_output=(
        "A structured report with framework versions, benchmark scores, "
        "GitHub star counts, and key feature comparisons."
    ),
    agent=researcher,
)

write_task = Task(
    description="Write a concise 500-word developer-facing comparison article based on the research.",
    expected_output="A 500-word Markdown article with a comparison table and code snippets.",
    agent=writer,
    context=[research_task],   # receives output of research_task as context
)

# Assemble and kick off
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.sequential,
    verbose=True,
)

result = crew.kickoff()
print(result.raw)

Example: CrewAI Flows for Event-Driven Pipelines

from crewai.flow.flow import Flow, listen, start
from pydantic import BaseModel

class ResearchState(BaseModel):
    topic: str = ""
    research_report: str = ""
    final_article: str = ""

class ContentFlow(Flow[ResearchState]):

    @start()
    def set_topic(self):
        self.state.topic = "LangGraph vs CrewAI in production 2026"
        return self.state.topic

    @listen(set_topic)
    def run_research(self, topic: str):
        # Invoke a researcher crew or direct LLM call
        self.state.research_report = f"Deep research findings on: {topic}"
        return self.state.research_report

    @listen(run_research)
    def write_article(self, report: str):
        self.state.final_article = f"Article synthesised from: {report}"
        return self.state.final_article

flow = ContentFlow()
flow.kickoff()
print(flow.state.final_article)

from autogen import AssistantAgent, UserProxyAgent

llm_config = {
    "config_list": [{"model": "gpt-4o", "api_key": "YOUR_API_KEY"}],
    "temperature": 0,
    "timeout": 120,
}

# AssistantAgent: plans and writes code
assistant = AssistantAgent(
    name="CodingAssistant",
    llm_config=llm_config,

        "correct, well-commented Python code. End messages with TERMINATE when done."
    ),

# UserProxyAgent: executes code, no human interaction
user_proxy = UserProxyAgent(
    name="Executor",
    human_input_mode="NEVER",       # fully automated
    max_consecutive_auto_reply=10,

        "work_dir": "workspace",

        "timeout": 60,
    },
    is_termination_msg=lambda x: "TERMINATE" in x.get("content", ""),

user_proxy.initiate_chat(

OpenAI Agents SDK

The OpenAI Agents SDK (open-source, Python-first) is OpenAI's official framework for building production-grade agentic systems. It introduces four primitives — Agent, Runner, Tool, and Handoff — plus built-in tracing and guardrails, making it the simplest path to deploying agents backed by GPT-4o or o3.

Example: Agent with Tools

from agents import Agent, Runner, function_tool
import asyncio

@function_tool
def web_search(query: str) -> str:
    """Search the web for up-to-date information on a topic."""
    # In production: integrate Tavily or Brave Search
    return f"Top results for '{query}': [results here]"

@function_tool
def get_stock_price(ticker: str) -> dict:
    """Get the current stock price for a given ticker symbol."""
    # In production: call a financial data API
    return {"ticker": ticker.upper(), "price": 185.42, "currency": "USD"}

agent = Agent(
    name="ResearchAssistant",
    instructions=(
        "You are a financial research assistant. Use web_search to find "
        "context and get_stock_price for live prices. Always cite sources."
    ),
    tools=[web_search, get_stock_price],
    model="gpt-4o",
)

async def main():
    result = await Runner.run(agent, "What is the current AAPL price and recent news?")
    print(result.final_output)

asyncio.run(main())

Example: Guardrails for Input Validation

from agents import Agent, Runner, GuardrailFunctionOutput, input_guardrail
from pydantic import BaseModel
import asyncio

class SafetyCheck(BaseModel):
    is_safe: bool
    reason: str

safety_agent = Agent(
    name="SafetyChecker",
    instructions="Determine if the user request is safe and appropriate.",
    result_type=SafetyCheck,
    model="gpt-4o-mini",   # cheap model for guardrail pass
)

@input_guardrail
async def content_safety_guardrail(ctx, agent, input):
    result = await Runner.run(safety_agent, input, context=ctx.context)
    check: SafetyCheck = result.final_output
    return GuardrailFunctionOutput(
        output_info=check,
        tripwire_triggered=not check.is_safe,
    )

main_agent = Agent(
    name="MainAgent",
    instructions="You are a helpful assistant.",
    input_guardrails=[content_safety_guardrail],
    model="gpt-4o",
)

async def main():
    try:
        result = await Runner.run(main_agent, "How do I build a website?")
        print(result.final_output)
    except Exception as e:
        print(f"Guardrail triggered: {e}")

asyncio.run(main())

Pydantic AI

Pydantic AI brings the ergonomics of FastAPI to LLM agents. It enforces type safety from tool inputs through to the final structured output, uses dependency injection for clean testability, and integrates natively with the Pydantic V2 ecosystem used throughout modern Python stacks.

Example: Structured Output, Dependency Injection, and Tool

from pydantic import BaseModel
from pydantic_ai import Agent, RunContext
from dataclasses import dataclass

# Result schema — enforced on every agent run
class CompanyProfile(BaseModel):
    name: str
    industry: str
    employee_count: int
    founded_year: int
    summary: str

# Dependencies injected at runtime (never baked into the agent definition)
@dataclass
class Deps:
    company_db: dict    # real code: SQLAlchemy session, HTTP client, etc.

# Create agent
agent = Agent(
    "openai:gpt-4o",
    result_type=CompanyProfile,
    deps_type=Deps,
    system_prompt=(
        "You are a company analyst. Use the lookup_company tool to retrieve "
        "data and return a complete, accurate CompanyProfile."
    ),
)

# Tool with full type safety — validated at call time
@agent.tool
async def lookup_company(ctx: RunContext[Deps], company_name: str) -> dict:
    """Look up a company record in the database by its name."""
    return ctx.deps.company_db.get(company_name.lower(), {"error": "not found"})

# Run
import asyncio

async def main():
    db = {
        "acme corp": {
            "industry": "Technology",
            "employees": 1200,
            "founded": 2005,
        }
    }
    result = await agent.run("Give me a profile of Acme Corp.", deps=Deps(company_db=db))
    profile: CompanyProfile = result.data
    print(profile.model_dump_json(indent=2))

asyncio.run(main())

Example: Testing with TestModel

import pytest
from pydantic_ai import models
from pydantic_ai.models.test import TestModel

# TestModel returns predictable minimal outputs — no real LLM call
@pytest.mark.asyncio
async def test_company_agent_returns_profile():
    db = {"testco": {"industry": "Retail", "employees": 50, "founded": 2010}}
    deps = Deps(company_db=db)

    with models.override(TestModel()):
        result = await agent.run("Profile TestCo.", deps=deps)
        assert isinstance(result.data, CompanyProfile)
        # TestModel fills fields with sensible defaults
        assert result.data.name is not None
Type Safety from Tool Inputs to Final Output — No JSON Parsing Surprises Pydantic AI validates tool inputs at call time and enforces the result_type schema on every agent response. If the model returns malformed JSON or a wrong type, the agent retries automatically with a validation error message. This eliminates entire classes of runtime bugs that plague other frameworks where you manually parse response.content.

Example: LangGraph + Redis Long-Term Memory

from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.redis import RedisSaver
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import Qdrant
from langchain_core.messages import BaseMessage, HumanMessage, SystemMessage
from typing import TypedDict, Annotated, Sequence
import operator

# Long-term semantic memory: Qdrant vector store
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
memory_store = Qdrant.from_existing_collection(
    embedding=embeddings,
    collection_name="agent_long_term_memory",
    url="http://localhost:6333",
)

class AgentState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], operator.add]
    user_id: str

llm = ChatOpenAI(model="gpt-4o", temperature=0)

def retrieve_memory(state: AgentState) -> AgentState:
    """Pull the top-3 semantically relevant long-term memories for this query."""
    query = state["messages"][-1].content
    docs = memory_store.similarity_search(
        query, k=3,
        filter={"user_id": state["user_id"]}
    )
    if docs:
        memory_text = "\n".join(d.page_content for d in docs)
        sys_msg = SystemMessage(content=f"Relevant past context:\n{memory_text}")
        return {"messages": [sys_msg]}
    return {}

def save_memory(state: AgentState) -> AgentState:
    """Persist the assistant's last response to long-term memory."""
    last = state["messages"][-1].content
    memory_store.add_texts(
        [last],
        metadatas=[{"user_id": state["user_id"]}]
    )
    return {}

def respond(state: AgentState) -> AgentState:
    response = llm.invoke(state["messages"])
    return {"messages": [response]}

# Build graph with Redis-backed short-term persistence
graph = StateGraph(AgentState)
graph.add_node("retrieve_memory", retrieve_memory)
graph.add_node("respond", respond)
graph.add_node("save_memory", save_memory)

graph.add_edge(START, "retrieve_memory")
graph.add_edge("retrieve_memory", "respond")
graph.add_edge("respond", "save_memory")
graph.add_edge("save_memory", END)

checkpointer = RedisSaver.from_conn_string("redis://localhost:6379")
app = graph.compile(checkpointer=checkpointer)
Context Window = Working Memory — Summarise or Evict Old Turns Aggressively The context window is your agent's working memory. As conversation grows, costs rise linearly and attention quality degrades. Summarise or evict old turns after 10–15 exchanges. For long-running agents, externalise all state to a persistent store and pull in only what's relevant via similarity search. Never let an agent's context grow unbounded in production.

Example: LangGraph Supervisor + Subagent Routing

from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI
from langchain_core.messages import BaseMessage, HumanMessage, SystemMessage
from typing import TypedDict, Annotated, Sequence, Literal
import operator

class SupervisorState(TypedDict):
    messages: Annotated[Sequence[BaseMessage], operator.add]
    next_agent: str

llm = ChatOpenAI(model="gpt-4o", temperature=0)
AGENTS = ["researcher", "coder", "writer"]

def supervisor_node(state: SupervisorState) -> SupervisorState:
    """Routes to the best specialist agent or finishes the task."""
    routing_prompt = (
        f"You are a supervisor routing tasks to: {AGENTS}.\n"
        "Reply with ONLY the agent name to call next, or 'FINISH' if the task is complete."
    )
    resp = llm.invoke([SystemMessage(content=routing_prompt)] + list(state["messages"]))
    return {"next_agent": resp.content.strip()}

def researcher_node(state: SupervisorState) -> SupervisorState:
    resp = llm.invoke([
        SystemMessage(content="You are a research expert. Provide factual, cited answers."),
        *state["messages"]
    ])
    return {"messages": [resp], "next_agent": "supervisor"}

def coder_node(state: SupervisorState) -> SupervisorState:
    resp = llm.invoke([
        SystemMessage(content="You are a Python expert. Write clean, runnable, commented code."),
        *state["messages"]
    ])
    return {"messages": [resp], "next_agent": "supervisor"}

def writer_node(state: SupervisorState) -> SupervisorState:
    resp = llm.invoke([
        SystemMessage(content="You are a technical writer. Produce clear, concise documentation."),
        *state["messages"]
    ])
    return {"messages": [resp], "next_agent": "supervisor"}

def route(state: SupervisorState) -> Literal["researcher", "coder", "writer", "__end__"]:
    agent = state.get("next_agent", "FINISH")
    return END if agent == "FINISH" else agent

graph = StateGraph(SupervisorState)
for name, fn in [("supervisor", supervisor_node), ("researcher", researcher_node),
                  ("coder", coder_node), ("writer", writer_node)]:
    graph.add_node(name, fn)

graph.add_edge(START, "supervisor")
graph.add_conditional_edges("supervisor", route)
for agent in AGENTS:
    graph.add_edge(agent, "supervisor")

app = graph.compile()
result = app.invoke({"messages": [HumanMessage(content="Build a web scraper and document it.")]})
Cascading Failures — One Slow Subagent Blocks the Whole Pipeline In multi-agent systems, one stuck or slow subagent blocks the entire pipeline. Always set per-call timeouts, implement circuit breakers for repeated failures, and define explicit fallback behaviours (return partial results, skip optional agents). A supervisor that waits indefinitely for a worker is the most common production incident pattern in agentic systems deployed at scale.

Production Agents

Running agents in production requires infrastructure that goes far beyond the happy path. Observability, cost controls, retry logic, and graceful degradation are not optional extras — they are the core of the product.

Production Checklist

Observability

Trace every LLM call, tool invocation, and token count. Use LangSmith, Arize, or Datadog. Alert on p95 latency and error rate spikes.

Cost Budget

Set per-user and per-session token budgets. Track spend in real time via LiteLLM. Kill runaway agents before they exhaust quota.

Retry Logic

Exponential backoff on 429 and 503. Distinguish retryable errors from fatal 400 bad-request errors. Do not retry validation failures.

Human Escalation

Define escalation triggers: low confidence score, high-stakes action, three consecutive failures. Build the approval UI before launch.

Stateful Deployment

Persist agent state externally (Redis, Postgres). Stateless app servers only. Enables horizontal scaling and crash recovery.
