SECTION 01

React Fundamentals

React is a declarative UI library for building component trees. Understanding its mental model — UI as a function of state — is the foundation everything else builds on.

Core Mental Model

UI = f(state)    // React re-renders when state changes, producing a new UI description

React does not mutate the DOM directly. It maintains a virtual DOM (VDOM) — a lightweight JavaScript object tree describing what the UI should look like. On state change, React computes a new VDOM, diffs it against the previous (reconciliation), and applies only the minimal set of real DOM mutations.

JSX

JSX is syntactic sugar for React.createElement(type, props, ...children). Babel/TypeScript transpiles it:

// JSX
const el = <Button color="blue">Click me</Button>;

// Transpiled (React 17+ automatic runtime)
const el = _jsx(Button, { color: "blue", children: "Click me" });

Component Types

Function Components (Modern)

Plain JavaScript functions that accept props and return JSX. Hooks provide state and lifecycle. Recommended since React 16.8.

Class Components (Legacy)

ES6 classes extending React.Component. Use lifecycle methods. Still supported but not idiomatic in new code.

Props vs State

PropsState
OwnerParent componentThe component itself
Mutable by component?No (read-only)Yes (via useState / setState)
Triggers re-render?Yes (when parent re-renders)Yes (on change)
AnalogyFunction argumentsInternal memory

Controlled vs Uncontrolled Components

// Controlled: React owns the value
function ControlledInput() {
  const [value, setValue] = useState('');
  return <input value={value} onChange={e => setValue(e.target.value)} />;
}

// Uncontrolled: DOM owns the value, accessed via ref
function UncontrolledInput() {
  const ref = useRef(null);
  return <input ref={ref} defaultValue="initial" />;
}

Keys in Lists

Keys must be stable and unique among siblings. Using array index as key causes bugs when items reorder — React reuses DOM nodes in place and only updates their content, so input values, focus, and animations don't move with the data.

Index-as-key bug If you reverse a list with index keys, each DOM node stays in position and only its content is patched. Local state (typed text, checkbox checked) stays at the same DOM position, not with the moved data.
SECTION 02

Hooks Deep Dive

Hooks let function components use state, side effects, context, and more without class boilerplate. Understanding the rules and internal mechanics is mandatory for senior interviews.

Rules of Hooks

  • Only call hooks at the top level — never inside loops, conditions, or nested functions
  • Only call hooks from React function components or custom hooks
  • React tracks hooks by call order — any conditional hook call shifts all subsequent hooks onto wrong slots

useState

const [count, setCount] = useState(0);

// Functional update: use when new state depends on previous
setCount(prev => prev + 1);

// Lazy initialisation: expensive initial value computed once
const [data, setData] = useState(() => JSON.parse(localStorage.getItem('data') ?? '[]'));

useEffect

// Runs after every render (no deps array)
useEffect(() => { });

// Runs once on mount
useEffect(() => {
  const sub = subscribe(id);
  return () => sub.unsubscribe();  // cleanup on unmount
}, []);

// Runs when id changes
useEffect(() => {
  fetchUser(id).then(setUser);
}, [id]);
useEffect timing useEffect fires after the browser paints. For DOM measurements before paint use useLayoutEffect (synchronous, fires after DOM mutation but before paint — can block visual updates).

useRef

// DOM reference
const inputRef = useRef(null);
inputRef.current?.focus();

// Mutable value that persists without triggering re-render
const timerRef = useRef(null);
timerRef.current = setTimeout(() => {}, 1000);

// Storing previous value
const prevCountRef = useRef(count);
useEffect(() => { prevCountRef.current = count; });

useMemo & useCallback

// useMemo: memoises a computed value
const sortedList = useMemo(
  () => [...items].sort((a, b) => a.name.localeCompare(b.name)),
  [items]
);

// useCallback: memoises a function reference
const handleClick = useCallback(
  (id) => dispatch({ type: 'SELECT', id }),
  [dispatch]
);
Don't over-memo useMemo and useCallback have a cost. Only use them when the computation is genuinely expensive, or when the value is passed as a prop to a React.memo child where referential stability matters.

useReducer

function reducer(state, action) {
  switch (action.type) {
    case 'increment': return { ...state, count: state.count + 1 };
    case 'reset': return { count: 0, loading: false };
    default: return state;
  }
}

const [state, dispatch] = useReducer(reducer, { count: 0, loading: false });

Custom Hooks

function useWindowSize() {
  const [size, setSize] = useState({ width: window.innerWidth, height: window.innerHeight });
  useEffect(() => {
    const handler = () => setSize({ width: window.innerWidth, height: window.innerHeight });
    window.addEventListener('resize', handler);
    return () => window.removeEventListener('resize', handler);
  }, []);
  return size;
}

const { width, height } = useWindowSize();
SECTION 03

React Internals & Fiber

React Fiber (React 16) rewrote the reconciler to support asynchronous, interruptible rendering. Understanding Fiber separates mid-level from senior React engineers.

What is Fiber?

Fiber is both an internal data structure (one Fiber node = one unit of work for a component) and a new reconciler architecture that can pause, resume, and prioritise rendering work. Before Fiber, rendering used a synchronous recursive call stack that could not be interrupted, causing dropped frames on large trees.

Fiber Node (simplified)

// Each component in the tree has a Fiber node
{
  type: 'div' | MyComponent,   // element type
  stateNode: DOMElement | null,
  return: Fiber,               // parent
  child: Fiber,                // first child
  sibling: Fiber,              // next sibling (linked list)
  memoizedState: Hook | null,  // linked list of this component's hooks
  effectTag: INSERT | UPDATE | DELETE,
  alternate: Fiber             // double-buffering: current vs work-in-progress
}

Reconciliation — The Diffing Algorithm

React's diffing algorithm runs in O(n) via two assumptions:

  • Different element types produce different trees: if a div changes to span, React unmounts the entire subtree
  • Keys identify stable elements: matching keys reuse the existing Fiber node and DOM element
  Render Phase (async, interruptible)        Commit Phase (sync, cannot pause)
  ──────────────────────────────────        ────────────────────────────────────
  Build work-in-progress Fiber tree         Apply all DOM mutations at once
  Run component functions                   Call useLayoutEffect cleanup + setup
  Compute new state                         Call useEffect cleanup + setup (async)
  Tag nodes: INSERT / UPDATE / DELETE       Call ref callbacks
  Can be paused by Scheduler                Must complete in one synchronous tick

Concurrent Features (React 18+)

useTransition

Mark a state update as non-urgent. React can interrupt it to handle urgent updates (typing, clicking). UI stays interactive while transition renders in background.

Suspense

Declaratively show fallback while async work resolves. Works with React.lazy() for code splitting and frameworks like TanStack Query for data.

useDeferredValue

Defer an expensive derived value. React renders with old value first (keeping UI responsive), then re-renders with deferred value when idle.

Automatic Batching

React 18 batches all setState calls in any async context (setTimeout, fetch callbacks) into a single re-render. Pre-18 only synthetic event handlers were batched.

// useTransition: keep input responsive while filtering large list
const [isPending, startTransition] = useTransition();

function handleChange(e) {
  setInputValue(e.target.value);           // urgent: immediate
  startTransition(() => {
    setFilteredList(expensiveFilter(e.target.value));  // non-urgent: deferrable
  });
}

React.memo

const Chart = React.memo(function Chart({ data, onSelect }) {
  // Only re-renders when data or onSelect reference changes
  return <HeavyVisualization data={data} />;
}, (prev, next) => prev.data.id === next.data.id);  // optional custom comparator

Modern React development relies on a rich tooling ecosystem. Understanding how build tools and meta-frameworks interact is essential for senior frontend roles.

Next.js Rendering Strategies

SSG (Static Site Generation)

HTML at build time. CDN-served. Use for rarely-changing content (blog, docs). Fastest TTFB.

SSR (Server-Side Rendering)

HTML per request on server. Fresh data. Use for personalised, SEO-critical dynamic pages.

ISR (Incremental Static Regen)

Static page regenerated in background after revalidate window. CDN speed + fresh data.

React Server Components

Next.js App Router default. Run on server only — direct DB access, no client JS shipped. Client components opt-in with 'use client'.

// RSC: Server Component — no 'use client', async directly in component
async function ProductPage({ params }) {
  const product = await db.products.findById(params.id);  // direct DB access
  return (
    <div>
      <h1>{product.name}</h1>
      <AddToCartButton id={product.id} />  {/* Client component */}
    </div>
  );
}

Code Splitting

// Route-level code splitting
const Dashboard = React.lazy(() => import('./Dashboard'));

<Suspense fallback={<Spinner />}>
  <Dashboard />
</Suspense>
SECTION 05

Advanced Patterns

Structural patterns solve recurring design problems in React: sharing logic, building flexible APIs, and managing component communication without tight coupling.

Container / Presentational Split

// Container: handles state and side effects
function UserProfileContainer({ userId }) {
  const { data, isLoading } = useQuery(['user', userId], fetchUser);
  if (isLoading) return <Skeleton />;
  return <UserProfile user={data} />;
}

// Presentational: pure function of props, easy to test
function UserProfile({ user }) {
  return <div><h2>{user.name}</h2><p>{user.email}</p></div>;
}

Portal Pattern

import { createPortal } from 'react-dom';

function Modal({ children, onClose }) {
  return createPortal(
    <div className="modal-overlay" onClick={onClose}>
      <div className="modal-content" onClick={e => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body   // renders outside parent hierarchy
  );
}

Error Boundaries

class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError() { return { hasError: true }; }

  componentDidCatch(error, info) { logErrorToService(error, info.componentStack); }

  render() {
    if (this.state.hasError) return this.props.fallback;
    return this.props.children;
  }
}

Optimistic Updates

async function addTodo(text) {
  const tempId = crypto.randomUUID();
  setTodos(prev => [...prev, { id: tempId, text, pending: true }]);  // optimistic
  try {
    const saved = await api.createTodo(text);
    setTodos(prev => prev.map(t => t.id === tempId ? saved : t));   // confirm
  } catch {
    setTodos(prev => prev.filter(t => t.id !== tempId));            // rollback
  }
}

Prop Lifting vs Context

Lift state to the nearest common ancestor when 2–3 siblings share it. Switch to Context when the state needs to reach components that are many levels deep, or when prop-drilling makes the intermediate components aware of data they don't use.

SECTION 06

Compound Components

Compound components share implicit state via context, giving consumers full layout control without a large props surface — analogous to how native HTML elements like select/option work together.

Why Compound Components?

// Props explosion — rigid, hard to customise layout
<Select options={opts} value={v} onChange={fn} label="Pick one" icon={...} footer={...} />

// Compound — consumer controls structure
<Select value={v} onChange={fn}>
  <Select.Trigger>{selectedLabel}</Select.Trigger>
  <Select.Dropdown>
    {opts.map(o => <Select.Option key={o.id} value={o.id}>{o.label}</Select.Option>)}
  </Select.Dropdown>
</Select>

Implementation with Context

const SelectContext = createContext(null);

function useSelectContext() {
  const ctx = useContext(SelectContext);
  if (!ctx) throw new Error('Must be used within Select');
  return ctx;
}

function Select({ children, value, onChange }) {
  const [isOpen, setIsOpen] = useState(false);
  return (
    <SelectContext.Provider value={{ value, onChange, isOpen, setIsOpen }}>
      <div className="select">{children}</div>
    </SelectContext.Provider>
  );
}

function Trigger({ children }) {
  const { isOpen, setIsOpen } = useSelectContext();
  return <button onClick={() => setIsOpen(!isOpen)}>{children}</button>;
}

function Option({ value, children }) {
  const ctx = useSelectContext();
  return (
    <div
      className={ctx.value === value ? 'selected' : ''}
      onClick={() => { ctx.onChange(value); ctx.setIsOpen(false); }}
    >{children}</div>
  );
}

Select.Trigger = Trigger;
Select.Option = Option;
Real-world examples Radix UI and Headless UI are built entirely on the compound component pattern — they ship zero styles but full accessibility, and consumers compose the parts in their own markup.
SECTION 07

Render Props & Higher-Order Components

Both patterns solve logic reuse before hooks existed. HOCs are still common in codebases and libraries. You need to understand, implement, and critique both patterns in interviews.

Render Props

A function prop that a component calls to know what to render. The component owns logic; the consumer owns presentation.

function MouseTracker({ render }) {
  const [pos, setPos] = useState({ x: 0, y: 0 });
  return (
    <div onMouseMove={e => setPos({ x: e.clientX, y: e.clientY })}>
      {render(pos)}
    </div>
  );
}

// Usage
<MouseTracker render={({ x, y }) => <p>Mouse: {x}, {y}</p>} />

// Modern equivalent — custom hook (no nesting, same logic reuse)
const { x, y } = useMousePosition();

Higher-Order Components

// withAuth: HOC that guards routes
function withAuth(WrappedComponent) {
  return function AuthGuard(props) {
    const { user } = useAuth();
    if (!user) return <Navigate to="/login" />;
    return <WrappedComponent {...props} />;
  };
}

const ProtectedDashboard = withAuth(Dashboard);

HOC Caveats (say these in interviews)

HOC pitfalls
  • Prop name collisions — HOC props may shadow wrapped component props
  • Refs don't pass through — need React.forwardRef
  • Extra wrapper nodes in DevTools — always set displayName
  • Composition order matters — withAuth(withLogger(C)) is not the same as withLogger(withAuth(C))

Comparison

PatternLogic ReuseNestingPreferred?
Custom HooksYesNoneYes — modern default
Render PropsYesCan nestWhen component tree semantics matter
HOCYesExtra wrapper nodesCross-cutting (auth guards, logging)
SECTION 08

State Management

React's built-in state handles most cases. External state managers are warranted when state is shared across many component subtrees, needs to outlive the tree, or requires sophisticated devtools.

Decision Tree

  Does state need to be shared beyond the component?
        |
        No  ->  useState / useReducer (local state)
        |
        Yes
         |
         +-- Only across a subtree? -> useContext + useReducer
         |
         +-- Across the whole app?
              |
              +-- Server data (fetch, cache, sync) -> TanStack Query / SWR
              |
              +-- Client global state
                    +-- Simple  ->  Zustand
                    +-- Derived ->  Jotai / Recoil
                    +-- Large teams / time-travel debug ->  Redux Toolkit

Zustand

import { create } from 'zustand';

const useCartStore = create((set) => ({
  items: [],
  addItem: (item) => set(state => ({ items: [...state.items, item] })),
  removeItem: (id) => set(state => ({ items: state.items.filter(i => i.id !== id) })),
}));

// Component only re-renders when selected slice changes
function CartCount() {
  const count = useCartStore(state => state.items.length);
  return <span>{count}</span>;
}

TanStack Query

const { data, isLoading, error } = useQuery({
  queryKey: ['products', { category, page }],
  queryFn: () => api.getProducts({ category, page }),
  staleTime: 5 * 60 * 1000,   // data fresh for 5 min
  gcTime: 30 * 60 * 1000,     // keep in cache 30 min after unmount
});

const mutation = useMutation({
  mutationFn: (product) => api.createProduct(product),
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['products'] }),
});

TypeScript with React

TypeScript and React are now inseparable in production codebases. Knowing the idiomatic patterns for typing props, events, generics, and hooks is a baseline for senior roles.

Typing Props

interface ButtonProps {
  variant: 'primary' | 'secondary' | 'danger';
  size?: 'sm' | 'md' | 'lg';
  onClick?: (event: React.MouseEvent<HTMLButtonElement>) => void;
  children: React.ReactNode;
  disabled?: boolean;
}

// Extending native element props
interface InputProps extends React.InputHTMLAttributes<HTMLInputElement> {
  label: string;
  error?: string;
}

function Input({ label, error, ...inputProps }: InputProps) {
  return (
    <label>
      {label}
      <input {...inputProps} />
      {error && <span className="error">{error}</span>}
    </label>
  );
}

Typing Events & Hooks

// Events
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => setValue(e.target.value);
const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => { e.preventDefault(); };

// useState with nullable
const [user, setUser] = useState<User | null>(null);

// useRef
const inputRef = useRef<HTMLInputElement>(null);     // DOM ref
const countRef = useRef<number>(0);                  // mutable value

// Custom hook return type
function useToggle(initial = false): [boolean, () => void] {
  const [value, setValue] = useState(initial);
  return [value, () => setValue(v => !v)];
}

Generic Components

interface ListProps<T> {
  items: T[];
  getKey: (item: T) => string;
  renderItem: (item: T) => React.ReactNode;
}

function List<T>({ items, getKey, renderItem }: ListProps<T>) {
  return <ul>{items.map(item => <li key={getKey(item)}>{renderItem(item)}</li>)}</ul>;
}

// T inferred as User
<List items={users} getKey={u => u.id} renderItem={u => <UserCard user={u} />} />

forwardRef

const FancyInput = React.forwardRef<HTMLInputElement, InputProps>(
  function FancyInput({ label, ...props }, ref) {
    return <label>{label}<input ref={ref} {...props} /></label>;
  }
);

Useful Utility Types

type ButtonProps = React.ComponentProps<typeof Button>;  // extract props from component
type DivProps = React.HTMLAttributes<HTMLDivElement>;     // native element props
type AnyChildren = { children: React.ReactNode };         // anything renderable
SECTION 10

Interview Q&A Cheatsheet

Condensed answers to common senior React interview questions, structured to demonstrate architectural understanding rather than just API recall.

Common Questions

QuestionKey Points to Cover
What is the virtual DOM?JS object tree representing UI. React diffs old vs new to compute minimal DOM mutations. Avoids expensive direct DOM manipulation on every state change.
What is React Fiber?New reconciler (React 16). Fiber = unit of work. Enables interruptible rendering, priority scheduling, Suspense, concurrent mode.
When does a component re-render?1) Own state changes. 2) Parent re-renders (even same props). 3) Context value changes. 4) A hook it uses updates. Prevent with React.memo + stable prop references.
useEffect vs useLayoutEffect?useEffect fires after paint (async). useLayoutEffect fires after DOM mutation but before paint (sync, blocks paint). Use useLayoutEffect only for DOM measurements.
How does React.memo work?Shallow compares all props. If same, skips render. Requires stable function/object references as props — use useCallback/useMemo on parent side.
Why not use array index as key?React reuses DOM nodes by key. With index keys, reordering reuses nodes in place and only patches content — local state, focus, animations don't follow the data.
Compound vs props-based API?Compound avoids props explosion, gives consumers layout control, shares implicit state via context. Use for multi-part components (Tabs, Select, Accordion).
How to handle server state?TanStack Query: caching, deduplication, background refetch, staleTime. Don't use Redux for server data — it's the wrong abstraction.

Performance Optimisation Checklist

Memoisation

React.memo on expensive pure components. useMemo for expensive derived data. useCallback for handlers passed to memo children.

Virtualisation

Render only visible rows in large lists with TanStack Virtual or react-window. Reduces DOM nodes from thousands to ~20.

Code Splitting

React.lazy + Suspense per route. Dynamic imports for heavy libraries loaded on demand.

Concurrent Features

useTransition for non-urgent updates. useDeferredValue for expensive derived renders. Keeps clicks and typing responsive.

Red Flags to Avoid

Common interview mistakes
  • Mutating state directly: state.items.push(x) instead of creating new array
  • Missing deps in useEffect leading to stale closures or infinite loops
  • New object/function created in JSX on every render: breaks React.memo
  • Fetching data in render body without useEffect or Suspense
  • Using index as key when list order can change
